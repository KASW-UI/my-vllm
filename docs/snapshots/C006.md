# C006: Dynamic Generation State

## Goal
C005 的静态 batch 将所有 request 锁在一起，短 request 完成后仍占据 slot，新 request 无法中途加入。本阶段引入动态状态管理，每个 request 拥有独立生命周期，新 request 可随时加入、已完成 request 实时释放资源。

## New Features
- `engine/waiting_queue.py` — FCFS 等待队列
- `engine/running_queue.py` — 运行中 request 集合
- `engine/state_manager.py` — 状态管理器，协调三态转换
- 每个 request 独立 KVCache + step 计数
- 主循环：`while has_work(): step()` — 每步推进所有 running request 一个 token
- 新 request 可中途加入，已完成 request 即时释放

## Runtime Flow
```
main loop:
  while has_work():
    step()
      │
      ├─ Promote: waiting → running (fill slots)
      │     ├─ prefill each new request
      │     └─ store KVCache per request
      │
      ├─ Decode: one token per running request
      │     ├─ individual forward with past_key_values
      │     └─ sample → append to output_token_ids
      │
      └─ Collect: finished → move to finished list
            ├─ EOS detected → FINISHED_STOPPED
            ├─ max_tokens reached → FINISHED_LENGTH_CAPPED
            └─ cleanup: free KV cache

State transitions per request:
  WAITING ──promote──► RUNNING ──step──► ... ──EOS/limit──► FINISHED
                            ▲
  new request arrives ──────┘  (mid-execution join!)
```

## Current Capability
- ✅ 每个 request 独立生命周期
- ✅ 新 request 可中途加入（动态）
- ✅ 已完成 request 实时释放 slot
- ✅ Per-request KV cache 管理

## Current Limitation
- ❌ 调度逻辑内嵌在 StateManager 中（`if waiting: add`, `if running: continue`, `if finished: remove`）
- ❌ 无调度策略（仅 FCFS）
- ❌ 无预取/资源感知
- ❌ Per-step 单 request forward（无 batch 加速）

## Next Stage
