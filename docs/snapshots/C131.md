## What each sub-item did

### #1 — `v1/attention/metadata.py` → merge into `backend.py`

`CommonAttentionMetadata` was split into its own file with no vLLM
counterpart (`vllm/v1/attention/backend.py:412` defines it inline).
Moved into `backend.py` between the imports and the
`AttentionBackend` class. Three callers updated:

- `my_vllm/v1/attention/backends/triton_attn.py`
- `my_vllm/v1/attention/backends/flash_attn.py`
- `my_vllm/v1/worker/gpu_model_runner.py`

The test file `tests/test_C022_attention.py` was using the old
two-import style; collapsed into a single import from `backend`.

### #2 + #10 — `v1/attention/backends/ops/` → `v1/attention/ops/`

The `paged_attn.py` module is at `vllm/v1/attention/ops/paged_attn.py`,
not under `backends/`. Moved it with `git mv`; deleted the now-empty
`backends/ops/__init__.py`; created the matching
`v1/attention/ops/__init__.py` (empty, matching vLLM's empty file).

Two callers updated:

- `my_vllm/v1/attention/backends/flash_attn.py`
- `tests/test_C023_paged_attn.py`

`tests/test_C031_runtime.py` file-completeness list updated.

### #3 — `v1/attention/ops/triton_slot_mapping.py` → inline into `block_table.py`

The self-invented filename had no vLLM counterpart — vLLM's
`_compute_slot_mappings_kernel` lives at
`vllm/v1/worker/gpu/block_table.py:250`. Inlined both the
`@triton.jit _compute_slot_mappings_kernel` and the
`compute_slot_mapping` wrapper directly into `block_table.py`.
Renamed the kernel to match vLLM exactly
(`_compute_slot_mappings_kernel`, was `_slot_mapping_kernel`).
This also makes `BlockTables.compute_slot_mappings()` a one-call
wrapper, eliminating the intermediate `compute_slot_mapping()` that
just delegated to the kernel.

### #7 — `nixl_connector.py` → `connector.py`

Two `NixlConnector` classes previously existed (one in
`nixl/__init__.py`, one in `nixl/nixl_connector.py`) with conflicting
signatures. Renamed the file (vLLM canonical name) and collapsed
`__init__.py` to a thin re-export. The `__init__.py` keeps the three
metadata dataclasses (`NixlConnectorMetadata`,
`NixlConnectorHandshakeMetadata`, `NixlConnectorWorkerMetadata`) since
they have no `connector.py` equivalent and live as `nixl`-specific
metadata shapes.
