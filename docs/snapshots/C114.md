# C114: Attention layer + QKVParallelLinear — file-tree split & structural alignment

## Goal

Bring `my_vllm/model_executor/layers/attention/` and `my_vllm/model_executor/layers/linear.py:QKVParallelLinear` closer to vLLM's source structure.

The substantive change: the `Attention` nn.Module lived in `attention/__init__.py` (single-file layout that doesn't exist in real vLLM). Real vLLM has it in `attention/attention.py` with `attention/__init__.py` re-exporting. This commit splits it into the matching layout and tightens the `Attention` constructor signature to mirror vLLM.

`QKVParallelLinear` already had the right shape — this commit adds the two public surface pieces (`validate_shard_id`, `load_weights`) that real vLLM exposes, without touching the quant paths.

## New Features

### `attention/attention.py` (new, extracted from `attention/__init__.py`)

The `Attention(nn.Module, AttentionLayerBase)` class now lives in its own file. Signature, fields, methods mirror vLLM `Attention`:

- Constructor: `(num_heads, head_size, scale, num_kv_heads=None, alibi_slopes=None, cache_config=None, quant_config=None, logits_soft_cap=None, per_layer_sliding_window=None, prefix="", attn_type="DECODER", **extra_impl_args)`.
- Fields: `num_heads`, `head_size`, `head_size_v`, `num_kv_heads`, `scale`, `layer_name`, `attn_type`, `kv_cache`, `kv_cache_dtype`, `kv_cache_torch_dtype`, `quant_config`, `cache_config`, `calculate_kv_scales`, `dtype`, `use_direct_call`.
- `forward(q, k, v, output_shape=None, output_dtype=None)` — reads `attn_metadata[self.layer_name]` from the active ForwardContext, with fallback to the first entry when the layer_name is absent.
- `get_attn_backend()` → `FlashAttentionBackend` (selector hook in C117 will switch this).
- `get_kv_cache_spec(vllm_config)` → `FullAttentionSpec(block_size, num_kv_heads, head_size, dtype)`.
- `bind_kv_cache(kv_cache)` — widened signature to accept `tuple[Tensor, Tensor]` (the current runner binds `(k, v)` as a tuple).
- `extra_repr()` for `print(model)` readability.

### `attention/__init__.py` (slimmed down)

Now just `from .attention import Attention` plus a docstring explaining the scope reduction (no cross/encoder/MLA/PCP variants).

### `linear.py:QKVParallelLinear` (structural alignment)

- `validate_shard_id(shard_id)` — new method, mirrors vLLM. Raises `ValueError` for shard_ids outside `{"q", "k", "v", None}`.
- `_get_shard_offset_mapping` gains the `"total"` key (mirrors real vLLM).
- `load_weights(weights)` — new method, mirrors vLLM `QKVParallelLinear.load_weights`. Iterates `(name, weight)` pairs and dispatches to the Parameter's `weight_loader` with the loaded weight's `shard_id` attribute.

The quant-path code (`weight_loader_v2`, `_load_fused_module_from_checkpoint`, PackedColumnParameter, BlockQuantScaleParameter, etc.) is intentionally absent — my-vllm is unquantized-only.

## Runtime Flow

```
OPTForCausalLM.forward(input_ids, positions)
   └─ for layer in decoder.layers:
        layer.self_attn(hidden_states)         # OPTAttention
           ├─ qkv_proj(hidden_states)          # QKVParallelLinear
           ├─ attn(q, k, v)                    # Attention(nn.Module + AttentionLayerBase)
           │    ├─ get_forward_context()       # C113 metadata channel
           │    ├─ ctx.attn_metadata[layer_name]
           │    └─ self.impl.forward(q,k,v, kv_cache, attn_metadata, output)
           │         (impl from FlashAttentionBackend / TritonAttentionBackend)
           └─ out_proj(attn_output)
```

- `Attention.forward` falls back to "first entry" when the layer's name is missing from `attn_metadata` — the current runner always populates the per-layer dict, but the fallback is there for robustness.
- `QKVParallelLinear` quant path still absent (out of scope until P1 quantization work).
