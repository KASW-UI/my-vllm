# C004: Request Object

## Goal
C003 的 runtime 只能处理一个隐式 prompt，没有请求概念。本阶段引入 Request 对象，为每个推理请求提供明确的 ID、状态和生命周期管理。

## New Features
- `engine/request.py` — `Request` dataclass + `RequestStatus` enum
- 状态机：`WAITING → RUNNING → FINISHED_STOPPED | FINISHED_LENGTH_CAPPED`
- Request 持有：`request_id`、`prompt_token_ids`、`output_token_ids`、`status`
- `LLM.generate()` 改为接受 `Request`，生成过程中更新状态和输出 token

## Runtime Flow
```
main.py                              model.py
  │                                     │
  ├─ Request(id, prompt_text)           │
  │    status=WAITING                   │
  │    ↓tokenize                        │
  ├─ request.prompt_token_ids           │
  │    ↓                                │
  ├─ llm.generate(request) ────────────►│
  │                                     ├─ status=RUNNING
  │                                     ├─ prefill → K,V cache
  │                                     ├─ decode loop
  │                                     │    ├─ sample token
  │                                     │    └─ append to request.output_token_ids
  │                                     ├─ status=FINISHED_STOPPED
  │                                     │  or FINISHED_LENGTH_CAPPED
  │◄────────────────────────────────────│
  │    ↓                                │
  └─ print request.output_token_ids     │
```

## Current Capability
- ✅ 请求拥有唯一 ID 和状态
- ✅ 请求生命周期：WAITING → RUNNING → FINISHED
- ✅ 输出 token 累积在 Request 中

## Current Limitation
- ❌ 一次只能执行一个 request（generate 期间其他 request 无法调度）
- ❌ 无 waiting queue / running queue
- ❌ 无 Batch 支持
- ❌ 无 Scheduler 角色

## Next Stage
GPU 利用率低——一次只能执行一个 request。Commit 005 引入 Static Batch，允许同时 forward 多个 request。
