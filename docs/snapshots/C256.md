# C256 — KV Offload tiering (CPU / NVMe)

## Goal

Closes the A-level "KV Offload tiering (CPU / NVMe)" gap from
`phase3-distributed-runtime-plan.md`.  Phase 4 v2 progress: 7/10
commits closed.

C256 ships the **CPU offload concrete backend** + the **tiering
composing-manager scaffold** that future secondary-tier backends
(Storage / FS / P2P / ObjectStore) plug into.  No concrete
secondary tier ships here — that lands when a real workload
needs it.

## New Features

### 1. `my_vllm/v1/kv_offload/cpu/` package (NEW)

7 files, ~1100 lines total:

* **`common.py`** (~30 lines): `CPUOffloadingMetrics` (Prometheus
  metric-name constants) + `CPULoadStoreSpec` (CPU-side block-ID
  descriptor — numpy int64, asserts non-negative IDs).
* **`policies/`** subpackage (4 files):
  - `base.py` (~100 lines): `BlockStatus`
    (ctypes.Structure carrying `ref_cnt` + `block_id`; ref_cnt=-1
    marks "not yet ready") + `CachePolicy` ABC.
  - `lru.py` (~90 lines): real `LRUCachePolicy` impl using
    `OrderedDict` for O(1) LRU eviction + a separate full dict
    for fast lookup. Has `mark_evictable` /
    `mark_non_evictable` for ref-count transitions, and a
    protected-key list for atomic eviction (None on failure,
    no state change).
  - `arc.py` (~75 lines): `ARCCachePolicy` shell — declared for
    registry completeness; raises `NotImplementedError` on actual
    use. Real ARC ships when a scan-resistant deployment needs it.
  - `__init__.py` (facade).
* **`manager.py`** (~330 lines): real `CPUOffloadingManager`
  impl. Owns:
  - A pluggable `CachePolicy` (LRU or ARC shell).
  - A simple block-ID pool (free list + allocated count).
  - The `prepare_load` / `complete_load` ref-counting protocol
    (with eviction-protection for in-flight transfers).
  - The `prepare_store` / `complete_store` lifecycle (with
    eviction fallback + failure rollback that frees blocks).
  - An optional `counts` LRU (when `store_threshold ≥ 2`) for
    per-key lookup-frequency filtering.
  - Event emission when `enable_events=True` (consumed by the
    C252 event bus).
  - `reset_cache` / `take_events` lifecycle.
* **`gpu_worker.py`** (~280 lines): real
  `CPUOffloadingWorker` impl. Composes two
  `SingleDirectionOffloadingHandler` instances (one per
  direction) with stream-pool + event-pool + buffer-pool
  recycling for async GPU↔CPU transfers.
* **`spec.py`** (~180 lines): real `CPUOffloadingSpec` impl.
  - Reads `cpu_bytes_to_use` (required) + `eviction_policy`
    (default "lru") + `store_threshold` + `max_tracker_size`
    from `extra_config`.
  - Computes `num_blocks` from `cpu_bytes_to_use` /
    `worker_kv_bytes_per_block` / `world_size` (each chunk =
    `kv_bytes_per_block * world_size * blocks_per_chunk`).
  - `get_manager()` lazily builds a `CPUOffloadingManager`.
  - `get_worker()` lazily builds a `CPUOffloadingWorker`.
  - `build_metric_definitions()` emits Gauge / Histogram /
    Counter metadata (Prometheus wiring deferred to Phase 5).
* **`__init__.py`** (facade).

**vLLM scope reductions**:
- No `SharedOffloadRegion` (mmap + `cudaHostRegister`) — my-vllm
  uses plain `torch.zeros` + `pin_memory=True`. Avoids the
  C-extension dependency.
- No Triton `swap_blocks` kernel — my-vllm uses
  `torch.Tensor.copy_` for byte transfers (~5-10× slower than
  the vLLM C++ op but correct on any CUDA / CPU backend, and
  offload isn't latency-critical at my-vllm's scale).
- Single-group Dense path only — multi-group sub-block math
  (`blocks_per_chunk > 1` with multi-KV-group `GPULoadStoreSpec`)
  is a Phase 5 follow-up.

### 2. `my_vllm/v1/kv_offload/tiering/` package (NEW)

5 files, ~600 lines total:

* **`base.py`** (~190 lines): `TieringOffloadingMetrics` (Prometheus
  metric-name constants) + `JobMetadata` / `JobResult` dataclasses
  for async transfer bookkeeping + `ParentManager` ABC (interface
  secondary tiers use to call back into the composing manager) +
  `SecondaryTierManager` ABC (abstract secondary tier with
  `lookup` / `submit_store` / `submit_load` /
  `get_finished_jobs` / `on_schedule_end` / `has_pending_work`
  / `reset_cache` / `shutdown`).
* **`factory.py`** (~150 lines): `SecondaryTierFactory` lazy-
  loading registry + `ExampleSecondaryTierManager` shell
  pre-registered for testing.
* **`manager.py`** (~250 lines):
  - `CPUPrimaryTierOffloadingManager` — wraps a
    `CPUOffloadingManager` as the primary tier (CPU-side gateway
    for all GPU↔offload operations) + provides
    `get_kv_memoryview()` accessor (returns zero-length view in
    my-vllm; full mmap-backed view lands with `SharedOffloadRegion`
    in Phase 5).
  - `TieringOffloadingManager` — composing manager that holds
    one primary tier + N secondary tiers. Implements
    `OffloadingManager` (lookup fan-out + delegation) and
    `ParentManager` (`create_store_job` placeholder). The full
    cascade / promotion state machine lands when a concrete
    secondary tier ships.
* **`spec.py`** (~75 lines): `TieringOffloadingSpec` extends
  `CPUOffloadingSpec` + parses `secondary_tiers` list from
  `extra_config` + wires up `TieringOffloadingManager`.
* **`__init__.py`** (facade).

### 3. `OffloadingSpecFactory` built-in registrations

`my_vllm/v1/kv_offload/factory.py` extended:
- `_register_builtins()` lazily installs the
  `CPUOffloadingSpec` + `TieringOffloadingSpec` registrations
  (avoids eager CPU/Tiering imports at my-vllm startup).
- `_ensure_builtins_registered()` is called on every
  `get_spec_cls` / `create_spec` / `known_specs` call so built-
  ins survive the test suite's `reset()` calls.
- `reset()` clears the user registry but the built-ins get
  re-bootstrapped on the next lookup.

### 4. `my_vllm/v1/kv_offload/__init__.py` facade

Re-exports the full public surface from `base.py` + `config.py`
+ `factory.py` + `file_mapper.py` (C255) + `cpu/` + `tiering/`
(C256) for `from my_vllm.v1.kv_offload import ...`.

## Current Capability

* `CPUOffloadingSpec` concrete impl with full
  `OffloadingManager` + `OffloadingWorker` surface — async
  GPU↔CPU transfers, LRU eviction, store-threshold filtering,
  event emission, prefix-cache-friendly ref-counting.
* `LRUCachePolicy` real impl (OrderedDict-based, O(1) LRU
  eviction + protected-key support + mark_evictable /
  mark_non_evictable for ref-count transitions).
* `BlockStatus` (ctypes.Structure) — per-block ref_cnt +
  block_id with ref_cnt=-1 marking write-pending.
* `TieringOffloadingSpec` + `TieringOffloadingManager` —
  composing manager with CPU primary + N secondary tiers.
* `CPUPrimaryTierOffloadingManager` — wraps `CPUOffloadingManager`
  + provides `get_kv_memoryview()` accessor.
* `SecondaryTierFactory` + `ExampleSecondaryTierManager` shell
  (pre-registered) for testing the registry + factory plumbing.
* `OffloadingSpecFactory` built-ins (`CPUOffloadingSpec` +
  `TieringOffloadingSpec`) installed lazily — survive test
  `reset()` calls via `_ensure_builtins_registered`.
* 73 new test cases cover the full C256 surface (including
  end-to-end prepare_store + eviction + dedup +
  complete_store-failure-rollback).
* Legacy C200-C255 tests still pass (961 passed, was 888; +73
  C256 cases). 2 pre-existing C212 attention-match failures
  carry over (cosine NaN — unrelated).

## Current Limitation

* **No concrete secondary tier** (Storage / FS / P2P /
  ObjectStore). `ExampleSecondaryTierManager` is the only
  registered tier; it always MISSes lookups + raises on actual
  transfer (smoke test for the factory).
* **`SharedOffloadRegion` not vendored** — secondary tiers that
  need a real memoryview of the primary tier's buffer get a
  zero-length view. Lands with Phase 5 when a real secondary
  tier needs the buffer.
* **Single-group Dense path only** — multi-group sub-block
  math (`blocks_per_chunk > 1` with multi-KV-group
  `GPULoadStoreSpec`) is a Phase 5 follow-up.
* **No Prometheus emission** — `get_stats()` returns None.
  Metric metadata (Gauge / Histogram / Counter definitions) is
  preserved; Phase 5 wires the actual `OffloadingConnectorStats`.
* **No CUDA-Triton swap-blocks kernel** — uses
  `torch.Tensor.copy_` instead (~5-10× slower than the vLLM
  C++ op but correct on any backend).
* **Composing manager's cascade / promotion state machine is
  simplified** — secondary-tier store / load callbacks go
  through `submit_*` on the secondary tier itself; the actual
  async coordination is delegated to each secondary tier's
  `get_finished_jobs()`. Full coordinator lands when a real
  secondary tier ships.
