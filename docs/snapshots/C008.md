# C008: KV Cache Manager

## Goal
C007 的 Scheduler 决定执行 request 但不知道 GPU 显存是否足够。本阶段引入 KVCacheManager，在 Scheduler 与 KV cache 之间建立资源感知层。

## New Features
- `cache/allocator.py` — `KVCacheAllocator`：token-budget 追踪器
- `cache/kv_cache_manager.py` — `KVCacheManager`：request ↔ KV cache 映射管理
- Scheduler 在 `schedule()` 内调用 `allocate()` 预留资源
- StateManager 不再直接管理 `_caches: dict`，委托给 KVCacheManager

## Runtime Flow
```
Scheduler.schedule()
  │
  ├─ for each waiting candidate:
  │     kv_cache_manager.allocate(request)   ← "显存放得下吗?"
  │       │
  │       ├─ allocator.can_allocate(n_tokens)  ← 检查 budget
  │       ├─ allocator.reserve(rx_id, n)        ← 预留
  │       └─ create KVCache                     ← 绑定
  │
  │     if failed → put back in waiting, stop promoting
  │
  └─ return [newly_promoted]

StateManager.step()
  │
  ├─ _prefill(req):
  │     cache = kv_cache_manager.get_cache(rid)  ← 复用已分配 cache
  │     cache.prefill(model, input_ids)
  │     set_step / set_next_token
  │
  ├─ _decode_step(req):
  │     cache = kv_cache_manager.get_cache(rid)
  │     cache.decode(model, next_token)
  │     set_step / set_next_token
  │
  └─ on finish:
        kv_cache_manager.free(rid)  ← 释放资源
          ├─ allocator.release(rid)
          └─ remove KVCache
```

## Architecture
```
┌──────────┐     ┌──────────────────┐     ┌─────────────────┐
│ Scheduler│ ──► │ KVCacheManager   │ ──► │ KVCacheAllocator │
│          │     │  _caches: dict    │     │  _reserved: dict │
│ schedule │     │  allocate()/free()│     │  can_allocate()  │
│          │     │  get/set step/tok │     │  reserve/release │
└──────────┘     └──────────────────┘     └─────────────────┘
                         │
                         ▼
                   ┌──────────┐
                   │ KVCache  │ (per-request, 连续内存)
                   │ prefill  │
                   │ decode   │
                   └──────────┘
```

## Current Capability
- ✅ Scheduler 感知 KV cache 资源（alloc/free 接口）
- ✅ 显存不足时不盲目调度（back-pressure）
- ✅ KVCache 生命周期管理集中化

## Current Limitation
- ❌ 连续 KV cache（prefill 后固定大小的 tensor）导致碎片
- ❌ 无 Block 抽象（无法分块管理）
- ❌ 释放后产生不可合并的碎片区域
- ❌ 无 prefix caching

## Next Stage
连续 KV cache 释放后产生内存碎片，多 request 共享显存困难。Commit 009 引入 Paged KV Cache（BlockPool + BlockTable）。
