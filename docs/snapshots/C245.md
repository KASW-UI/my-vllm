# C245 — Async Scheduler + Lock-Free Queues

> Closes the A-level "Async Scheduler" gap from
> `phase3-distributed-runtime-plan.md` § Phase 3.
>
> Real `AsyncScheduler` with vLLM's spec-decode / structured-output /
> async-output bookkeeping + `LockFreeFCFSRequestQueue` /
> `MPMCRequestQueue` queue variants + performance microbenchmark.

## Goal

Reproduce vLLM's `AsyncScheduler` as a real subclass (not a stub) and
add the lock-free queue primitives that amortize scheduling overhead
in the EngineCore hot path.

Specific deliverables:

1. `AsyncScheduler` (real subclass) implementing:
   - `_spec_token_placeholders` (reusable list of `-1` of length
     `num_spec_tokens`)
   - `num_sampled_tokens_per_step` (AR=1, diffusion=0, multi-token=N)
   - `pp_size` + `current_step` (for PP microbatching, deferred)
   - `use_v2_model_runner` (False in my-vllm)
   - `_update_after_schedule` override (placeholder bookkeeping)
   - `_update_request_with_output` override (`async_tokens_to_discard`
     drain + placeholder decrement)

2. Base `Scheduler` hooks (`_update_after_schedule`,
   `_update_request_with_output`) added as no-ops so AsyncScheduler
   can override cleanly.

3. `Request.num_output_placeholders` + `Request.async_tokens_to_discard`
   fields + `SchedulerOutput.scheduled_spec_decode_tokens` /
   `num_spec_tokens_to_schedule` / `pending_structured_output_tokens`
   fields.

4. `LockFreeFCFSRequestQueue` (SPSC, `deque` + GIL atomicity) +
   `MPMCRequestQueue` (cross-thread safe, `queue.SimpleQueue` +
   internal `Lock`).

5. Performance microbenchmark: standard vs lock-free vs MPMC.

## Runtime Flow

```
EngineCore loop (single thread)
───────────────────────────────
schedule()                                 update_from_output()
   │                                            │
   ├─ chunk_continue                             │
   ├─ pull_new (waiting queue → running)         │
   ├─ cached_data assembly                       │
   ├─ _assemble_scheduler_output                 │
   │     ↓                                      │
   ├─ _update_after_schedule(out)  ← C245 hook  │
   │     (AsyncScheduler sets placeholder ids,  │
   │      increments num_output_placeholders,   │
   │      advances current_step)                │
   │                                            │
   ↓                                            ↓
WorkerRunner forward                          per-request update:
  → model forward                               _update_request_with_output(req, tokens)
  → sample tokens                              (AsyncScheduler drains async_tokens_to_discard
  → fill scheduled_spec_decode_tokens            then decrements placeholders)
  → fill real ids in placeholder slots
```

For SPSC scheduling (the common EngineCore case), the waiting queue
is `LockFreeFCFSRequestQueue` (deque, GIL-atomic, no lock overhead).
For MPMC scheduling (HTTP server + EngineCore), it's
`MPMCRequestQueue` (queue.SimpleQueue + internal lock).

## Current Capability

* **Real `AsyncScheduler`** with all hooks wired through the base
  `Scheduler`'s `_update_after_schedule` / `_update_request_with_output`.
* **`_spec_token_placeholders`** — reusable list mutated in place
  per step (zero allocation in the hot path).
* **Placeholder bookkeeping** — `num_output_placeholders` +
  `async_tokens_to_discard` track in-flight async output frames
  per request.
* **`pending_structured_output_tokens`** flag in `SchedulerOutput`
  for grammar-guided gen (always False in my-vllm until C223.5).
* **`scheduled_spec_decode_tokens` + `num_spec_tokens_to_schedule`**
  in `SchedulerOutput` for spec decoding (no-op in my-vllm until
  C264 wires EAGLE/Medusa).
* **`LockFreeFCFSRequestQueue`** — true SPSC lock-free via
  CPython GIL atomicity; zero `threading.Lock` overhead.
* **`MPMCRequestQueue`** — cross-thread safe via `queue.SimpleQueue`
  + internal `threading.Lock`; documented for the rare
  HTTP-server + EngineCore race.
* **40 tests** across 8 classes covering all paths.

## Current Limitation

* **No spec decoding** — EAGLE/Medusa not vendored; the
  `_spec_token_placeholders` list is all `-1`s of length 0.
* **No structured output** — `pending_structured_output_tokens`
  is always False.
* **No PP microbatching** — `current_step` increments but
  `next_decode_eligible_step` is not used (PP is config-only in
  my-vllm until C260+).
* **No v2 model runner** — `use_v2_model_runner = False`.
* **Async tokens clamping at 0** — defensive guard; in practice the
  base hook + async discard path should never let the placeholder
  counter go negative.
