## New Features

### 1. `examples/distributed_comm_benchmark.py` (NEW, 644 lines)

Holistic bandwidth / latency sweep across the 5 core collectives
(`all_reduce` / `all_gather` / `reduce_scatter` / `all_to_all` /
`broadcast`), comparing all backends vendored in my-vllm:

  * **torch.distributed** — NCCL / Gloo baseline (all 5 ops).
  * **CustomAllreduce** (C214) — CUDA IPC ring AR (single-node,
    world_size 2..8).
  * **SymmMemCommunicator** (C241) — NVLS AR (H100/GB200 only;
    graceful disable on non-NVLS hardware).
  * **AgRsAll2AllManager** (C240) — naive AllGather + ReduceScatter
    all-to-all.
  * **ShmMessageQueue** (C242) — same-host broadcast over SHM.

Two modes:

  * **Single-rank** (default) — runs on a single GPU/CPU.  Each
    backend is benchmarked in identity mode (world_size=1 fast path).
  * **Multi-process gloo** — `--gloo --world_size N` spawns `N`
    workers via `torch.multiprocessing.spawn` with the gloo backend.
    Round-trip correctness for broadcast / all_gather / all_reduce.

Single-source-of-truth CSV schema:

```
backend,op,size_bytes,num_elements,dtype,world_size,elapsed_us,alg_bw_GBps,bus_bw_GBps,note
```

Bandwidth formulas per NCCL convention:

  * `all_reduce`: `alg = 2·(n-1)/n · s / t`, `bus = 2·(n-1)·s / t`.
  * `all_gather` / `reduce_scatter`: `alg = s / t`, `bus = (n-1)·s / t`.
  * `all_to_all`: same as `all_gather`.
  * `broadcast`: `alg = s / t`, `bus = s / t`.

### 2. `docs/notes/communication-operators.md` (NEW, 390 lines)

Comprehensive notes covering:

  * **5 collectives** — semantics, per-rank wire bytes, algorithmic
    bandwidth, bus bandwidth, where each shows up in LLM serving.
  * **Algorithm taxonomy** — ring (Patariasuk & Yuan 2009), tree,
    halving-doubling, one-shot vs two-shot, gather-then-broadcast.
  * **Backend hierarchy** — op × backend matrix + code map.
  * **Hardware-bandwidth hierarchy** — NVLS / NVLink / PCIe / IB /
    RoCE / Gloo; effective bandwidth per bus.
  * **Backend dispatch** — `CudaCommunicator.all_reduce` chain
    (world_size=1 → symm_mem → custom_ar → NCCL).
  * **Decision tree** — given message size and world size, which
    backend wins for `all_reduce`.
  * **Sizing tables** — `SYMM_MEM_ALL_REDUCE_MAX_SIZES` (Hopper+)
    and `CUSTOM_ALL_REDUCE_MAX_SIZES` (single-node).
  * **Implementation in my-vllm** — `_build_available_backends` and
    the Backend dataclass.
  * **Risks / limitations** — single-rank latency, custom AR CUDA
    requirement, SymmMem NVLS requirement, SHM same-host, naive
    all-to-all is O(P²), no CUDA graph capture.
  * **Future work** — C250 NIXL KV Connector, C251 KV event bus,
    C262 CUDA VMM, C264 Spec decode runner, C265 MoE AllToAll.

## Runtime Flow

```
User runs:
  python examples/distributed_comm_benchmark.py
        │
        ▼
Initialize gloo world_size=1 process group
        │
        ▼
Build backend registry:
  ┌──────────────────────────────────────────────────────────────┐
  │ torch.dist    → all 5 ops (NCCL/Gloo)                      │
  │ custom_ar     → all_reduce (C214, CUDA IPC ring)            │
  │ symm_mem      → all_reduce (C241 NVLS; probe disabled?)    │
  │ ag_rs         → all_to_all (C240 AllGather+ReduceScatter)   │
  │ shm           → broadcast (C242 MessageQueue)              │
  └──────────────────────────────────────────────────────────────┘
        │
        ▼
For each (backend, size, dtype):
  warmup × 3  →  time × 20  →  compute alg/bus_bw
        │
        ▼
Emit CSV row to stdout
```

## Current Capability

* **Single-rank 5-op benchmark** — produces 117 CSV rows per dtype
  (13 sizes × 9 op×backend combinations).
* **Backend identity detection** — SymmMem correctly shows as
  unavailable on RTX 4060 (sm_89).
* **Multi-process gloo round-trip** — broadcast / all_gather /
  all_reduce correctness via `torch.multiprocessing.spawn`.
* **CSV parseable** — single header + 117 data rows per run.
* **Single-source-of-truth backend registry** — adding a new
  backend requires adding one entry to `_build_available_backends`.

## Current Limitation

1. **Single-rank latency is Python overhead** — the harness is
   correct but the absolute numbers are not useful for bandwidth
   diagnosis.  Real bandwidth needs a multi-GPU box with NCCL.
2. **No CUDA graph capture** — vLLM's
   `benchmark_device_communicators.py` captures CUDA graphs to
   remove launch overhead.  my-vllm's benchmark measures
   **eager-mode** latencies.
3. **No FlashInfer / QuickReduce / DeepEP runtime** — those
   backends are class shells (C244) but the benchmark correctly
   skips them.
4. **SymmMem probe only at cold-start** — the benchmark probes
   `disabled` once and reuses the result.  Hot-path reload of the
   SymmMemCommunicator (e.g. after CUDA device change) is not
   exercised.
5. **Custom AR backend is identity-only** — the C214 extension
   has the ring AR implementation, but the benchmark's
   single-rank path bypasses it.  Multi-rank custom AR would
   need the C214 IPC handshake (CUDA IPC handles + rendezvous).
