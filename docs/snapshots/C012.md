# C012: Executor

## Goal
C011 的 Worker 直接暴露给 StateManager，无法统一管理多 Worker。本阶段引入 Executor 抽象层，统一封装 Worker 的访问和调度，修复 C011 的封装破裂问题。

## New Features
- `executor/uniproc_executor.py` — `Executor` 抽象类 + `UniProcExecutor`
- `Worker.execute_prefill()` / `Worker.execute_decode()` — 封装 ModelRunner，StateManager 不再直调 runner
- `WorkerBase` 移除 `get_model_runner()` — ModelRunner 变为 Worker 内部实现细节
- StateManager 通过 `Executor → Worker` 执行（不再直接持有 Worker）

## Architecture
```
Before (C011 — encapsulation breach):
  StateManager
    ├─ self.worker = worker
    └─ self.runner = worker.get_model_runner()  ← 暴露内部！
         └─ self.runner.prefill()              ← 绕过了 Worker

After (C012 — fixed):
  StateManager
    └─ self.executor = UniProcExecutor(worker)
         └─ self.worker = executor.get_worker()
              └─ self.worker.execute_prefill(rid, ids, cache)  ← 正确封装
              └─ self.worker.execute_decode(rid, cache)

Execution path:
  main.py → Worker → UniProcExecutor → StateManager ──► Worker.execute_xxx() ──► ModelRunner
```

## Current Capability
- ✅ Executor 统一管理 Worker 访问
- ✅ Worker 完全封装 ModelRunner（无 get_model_runner() 泄露）
- ✅ UniProcExecutor 为 C013 多卡扩展预留结构
- ✅ StateManager 通过 Executor → Worker 执行
- ✅ world_size=1 单卡支持

## Current Limitation
- ❌ UniProcExecutor 仅单 Worker（无多卡 Tensor Parallel）
- ❌ 无 SchedulerOutput / ModelRunnerOutput 数据流
- ❌ Per-request 逐个执行（非 batch execute_model）
