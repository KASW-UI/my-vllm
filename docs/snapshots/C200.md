# C200: profiler — GPU profiling toolchain + roofline methodology

## Goal

建立 GPU 性能分析的「工具 + 方法 + 报告」三件套，对应 JD 硬性 #4
（GPU/CUDA 性能分析经验）。

策略：不引入新 kernel，只用 `torch.cuda.Event` + 可选 `ncu`/`nsys`
对现有 `triton_unified_attention` / `triton_reshape_and_cache_flash`
两热点 kernel 做 wall-clock / bandwidth / GFLOPS 基准；配套 roofline
方法论文档（`docs/notes/gpu-profiling.md`），把"如何看 profile 数
据"沉淀为项目知识。

依据：
- `vllm/benchmarks/attention_benchmarks/runner.py:run_do_bench` — 上游
  attention benchmark 模板。
- `vllm/benchmarks/benchmark_block_pool.py` — micro-bench 模式参考。
- NVIDIA Nsight Compute / Systems 官方文档（笔记 cite）。

## What C200 did

### 1. `examples/profile_attention.py` (~190 行)

`unified_attention` kernel 的 wall-clock + GFLOPS 基准：
- 扫描 `(batch_size, max_seq_len, head_size, num_kv_heads)` 四维
- 调用签名与 `my_vllm/v1/attention/backends/triton_attn.py:194` 完全
  一致（q 形状 (N, H_q, D)，k/v 缓存 BSND 布局 (num_blocks,
  block_size, H_kv, D)）
- 输出 CSV：`batch_size, max_seq_len, head_size, num_kv_heads,
  time_us, gflops, kv_cache_dtype, error`

### 2. `examples/profile_cache_write.py` (~150 行)

`triton_reshape_and_cache_flash` kernel 的带宽基准：
- 扫描 `(num_tokens, num_kv_heads, head_size, block_size, dtype)`
- 输出 CSV：`num_tokens, num_kv_heads, head_size, block_size,
  kv_cache_dtype, time_us, gb_per_s, error`

### 3. `docs/notes/gpu-profiling.md` (~250 行)

方法论文档，覆盖：
- Nsight Compute (`ncu`) 启动方式 + 关键 metric（SOL / memory
  throughput / occupancy / registers / shared mem）
- Nsight Systems (`nsys`) 用于 timeline / 通信 / 调度延迟
- PyTorch `torch.cuda.Event` 内置时序（脚本依赖）
- Roofline 模型公式 + RTX 4060 Laptop baseline（峰值 FP16 ~15
  TFLOPS boost / GDDR6 272 GB/s，machine AI ~28 FLOP/Byte）
- Occupancy 调优（Triton `num_warps` / `num_stages`）
- 注意力 kernel 三种 PD-aware 调度的 roofline 放置
- 实战工作流（profile → diagnose → optimize → commit）

### 4. `tests/test_C200_profile.py` (~100 行)

3 个 smoke 测试：
- `test_profile_attention_runs`：profile_attention.py 跑小 sweep 至
  少 1 行成功
- `test_profile_cache_write_runs`：同上
- `test_profile_reproducibility_within_30pct`：两次连跑 ratio < 1.3

## Runtime Flow (新增工具调用链)

```
$ ncu --kernel-name regex:.*unified_attention.* \
       python examples/profile_attention.py
  │
  └─→ unified_attention kernel launches → ncu collects SOL/occupancy/registers
      └─→ per-kernel report → roofline classification (compute vs memory bound)

$ python examples/profile_attention.py
  │
  └─→ for batch, seq in sweep:
        unified_attention(...)
        time_us = cuda.Event.elapsed_time / iters
        gflops = batch * seq * H * D * 2 / (time_us * 1e-6) / 1e9
      └─→ CSV row
```

## Current Limitation

- 仅在 RTX 4060 Laptop 上验证；H100/A100/B200 上 profile 结果需要
  重新跑（机器平衡点 AI 不同，roofline 斜率不同）。
- 当前 profile 是 wall-clock 一阶指标，**没有** `ncu` 报告。生产
  阶段（C232）应加上 `ncu --set full` CI run。
- profile_attention.py 当前只测 **decode-only**（`max_seqlen_q=1`）
  调度；prefill-only 和 chunked-prefill mixed 调度未覆盖（属于
  C211 unified attention depth 验证范围）。
- 没有 CUDA Graph capture 开销 profile（vLLM V1 关键优化，后续
  C220 阶段补）。
