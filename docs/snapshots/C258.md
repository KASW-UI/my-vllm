# C258 — PD Disaggregation Benchmark (A-level gap)

**Status**: Closed (Phase 4 v2: 9/10)

## Goal

Provide a single-source-of-truth benchmark harness that measures the
prefill → decode KV transfer across the in-process shared-memory
backend (the C250/C251/C253 path) and projections for NIXL RDMA
hardware (NVLink / IB HDR / IB NDR / RoCE).  Output is a single CSV
with P50/P99/mean latency + effective bandwidth for every
(``num_tokens``, model geometry, mode) combination.

## New Features

| Surface | Description |
|---|---|
| `examples/pd_disaggregated_benchmark.py` (NEW, ~430 lines) | CLI benchmark: `--iters` (default 20), `--num-tokens` (default 256 512 1024 2048), `--num-layers`/`--num-kv-heads`/`--head-size`/`--block-size` (default OPT-125m shape), `--include-rdma` flag (also includes the 4 RDMA modes), `--device` (cuda/cpu), `--quiet` (suppress log rows). |
| `KvTransferParams` | Per-transfer shape: `num_tokens × num_layers × num_blocks × block_size × num_kv_heads × head_size × 2` (K+V) bytes. `num_blocks_for_tokens` (ceil), `bytes_per_kv_block`, `total_kv_bytes` matching vLLM's per-block math. |
| `BenchResult` | CSV row dataclass: `mode`, `medium`, `num_tokens`, `num_layers`, `num_kv_heads`, `head_size`, `block_size`, `num_blocks`, `kv_bytes`, `iteration`, `p50_us`, `p99_us`, `mean_us`, `min_us`, `gbytes_per_sec`, `note`. |
| `RdmaModeConfig` | Frozen dataclass: `name`, `medium`, `latency_per_byte_ns`, `per_message_overhead_us`, `link_bw_GBps`, `note`. `from_link_bw(...)` factory derives `latency_per_byte_ns` from link BW. |
| `DEFAULT_RDMA_MODES` | 4 calibrated modes: `nvlink` (50 GB/s, 2 μs), `ib_hdr` (25 GB/s, 10 μs), `ib_ndr` (50 GB/s, 8 μs), `roce` (20 GB/s, 15 μs). |
| `RdmaSimulator` | Pure-function latency floor: `elapsed_us(nbytes) = per_message_overhead_us + nbytes * latency_per_byte_ns / 1e3`. `gbytes_per_sec` for the round-trip. |
| `bench_in_process_transfer` | Real P→D SHM transfer: allocate GPU paged KV cache + pinned SHM buffer + per-layer `tensor.copy_()` (mirrors the C250 `NixlBaseConnector.save_kv_layer` flow). |
| `bench_rdma_simulated_transfer` | `time.sleep(simulator.elapsed_us(total_bytes))` — pure-function, deterministic, no system load dependency. |
| `percentile` / `summarize` | Linear-interpolation P50/P99 (mirrors vLLM nvtx helpers). |
| `run_benchmark` | Sweep over `num_tokens_list` × modes; returns `list[BenchResult]`. |
| CSV output | 16 columns, one row per (size, mode, dtype) cell. Header + rows printed to stdout. |

## Runtime Flow

```
User invocation
  │
  ├─ argparse: --iters, --num-tokens, --num-layers, --num-kv-heads,
  │            --head-size, --block-size, --include-rdma, --device, --quiet
  │
  ├─ _make_param_grid(num_tokens_list) → list[KvTransferParams]
  │     For each (num_tokens):
  │       KvTransferParams(num_tokens, num_layers, num_kv_heads,
  │                         head_size, block_size, num_blocks)
  │
  ├─ For each params:
  │     ├─ bench_in_process_transfer(params, iters, device)
  │     │     ├─ Allocate (num_layers, num_blocks, block_size, num_kv_heads,
  │     │     │           head_size) GPU K + V tensors
  │     │     ├─ Allocate pinned SHM CPU buffers (dst_k, dst_v)
  │     │     ├─ For each iteration:
  │     │     │     ├─ t0 = perf_counter()
  │     │     │     ├─ For each layer: dst_k.copy_(src_k.cpu()); dst_v.copy_(src_v.cpu())
  │     │     │     ├─ tor elapsed = (perf_counter() - t0) * 1e6
  │     │     └─ → list[float] (μs per iteration)
  │     │     → summarize → p50/p99/mean/min → BenchResult(mode="in_process")
  │     │
  │     └─ If --include-rdma:
  │         For each cfg in DEFAULT_RDMA_MODES:
  │           ├─ bench_rdma_simulated_transfer(params, iters, cfg)
  │           │     ├─ simulator = RdmaSimulator(cfg)
  │           │     ├─ For each iteration:
  │           │     │     ├─ t0 = perf_counter()
  │           │     │     ├─ time.sleep(simulator.elapsed_us(total_bytes) / 1e6)
  │           │     │     ├─ elapsed = (perf_counter() - t0) * 1e6
  │           │     └─ → list[float]
  │           └─ → BenchResult(mode=cfg.name, medium=cfg.medium)
  │
  └─ Output: CSV (one row per result) to stdout
```

## Current Capability

* **In-process** measurement — real SHM transfer on the same host
  (the C250/C251/C253 path).  Measures wire-format + Python overhead +
  the actual per-byte copy time.
* **RDMA-simulated** projection — calibrated for NVLink 4 (intra-node
  H100), IB HDR (ConnectX-7), IB NDR (ConnectX-8), RoCE v2 over 100G
  Ethernet.  Each mode has its own link BW + per-message overhead.
* **P50 / P99 / mean / min** timing per (size, mode) cell from
  configurable iterations.
* **Bandwidth utilization** in `gbytes_per_sec` (bytes / mean_us / 1e9).
* **CSV schema** with 16 columns; multiple backends share one CSV so
  the team can plot in Excel / DuckDB / pandas.
* **OPT-125m defaults** (12 layers, 12 KV heads, head_size=64,
  block_size=16, BF16) for direct match against the production model
  loading.  Override via CLI flags for any other shape.

## Current Limitation

* **No RDMA hardware backend**. The NIXL RDMA path is a calibrated
  simulation, not real wire-time measurement. Numbers are accurate
  enough for capacity planning (peak link BW) but ignore real-world
  noise (incast congestion, PCIe contention, MTU overhead).
* **No cross-process / multi-GPU path**. The in-process mode is
  single-host single-GPU. Multi-GPU NCCL AllReduce transfer is
  benchmarked separately in `examples/distributed_comm_benchmark.py`
  (C248).
* **No prefix-cache hit scenario**. The benchmark assumes a fresh
  transfer (cold cache). In production, PD instances with prefix
  cache reuse skip the transfer entirely; that path is covered by
  the C253 PD disagg test (multi-PD instances).
* **Per-layer framing cost ignored**. The simulation treats the
  transfer as a single bulk operation. Production NIXL breaks the
  transfer into per-block descriptors with format-specific
  alignment; the wire-format overhead is small (~1-2 μs per block).
* **No block-quantization awareness**. The benchmark assumes BF16 /
  FP16.  The C220/C224 FP8 / INT8 / INT4 paths would change the
  effective bytes/transfer and need separate sweeps.
