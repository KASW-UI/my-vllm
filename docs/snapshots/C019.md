# C019: Paged KV Block Table

## Goal

Replace Python-list BlockTable with GPU tensor BlockTables + slot_mappings,
establishing the logical→physical block mapping layer required for
PagedAttention in C022/C023.

## New Features

- `v1/worker/gpu/block_table.py` — BlockTables class:
  - GPU tensor block_table [max_reqs, max_blocks] int32
  - GPU tensor slot_mappings [max_tokens] int64
  - append_block_ids(req_index, block_ids) — populate block table
  - compute_slot_mappings(query_start_loc, positions, num_tokens)
    → calculates slot_id = block_id × block_size + offset
- GPUModelRunner now assigns per-request GPU slot indices and writes
  block IDs from SchedulerOutput into BlockTables
- Scheduler.schedule() passes block_ids in NewRequestData (from
  KVCacheManager.allocate_slots())
- InputBatch fields: +block_table_tensor, +slot_mapping, +query_start_loc
- Old cache/block_table.py reverted to compat wrapper

## Runtime Flow

```
EngineCore.step()
  → Scheduler.schedule()  ← NewRequestData.block_ids populated
  → GPUModelRunner.execute_model()
      → for new reqs: block_tables.append_block_ids(req_index, block_ids)
      → _prefill_batch():
          → build input_ids, positions
          → block_tables.compute_slot_mappings()
          → model forward (still HF past_key_values)
```

## Current Limitation

- Attention still uses HF past_key_values; slot_mappings not yet consumed
- No async CPU→GPU block table staging → C020+ (RequestState)
- BlockTables only updated for new requests (cached reqs pre-populated)
