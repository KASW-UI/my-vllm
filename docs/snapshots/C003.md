# C003: KV Cache

## Goal
C002 的 decode 阶段每一步都要重新计算全部历史 token 的 attention，计算量随序列长度平方增长。本阶段引入 KV Cache，将 decode 复杂度从 O(n²) 降到 O(n)。

## New Features
- `cache/kv_cache.py` — 连续内存 KV Cache
- `KVCache.prefill()` — 首次 forward 全 prompt，缓存所有 K、V
- `KVCache.decode()` — 每次只 forward 一个新 token，复用已有 KV
- 使用 HuggingFace `past_key_values` 机制（每层一个连续 K tensor + 一个连续 V tensor）
- `LLM.generate()` 改为 prefill + decode 两阶段

## Runtime Flow
```
Prefill:
  prompt token_ids
    ↓
  cache.prefill(model, input_ids)
    ↓
  all K,V stored in continuous tensors
    ↓
  logits → sample → first token

Decode:
  new token
    ↓
  cache.decode(model, new_token)
    ↓
  attention: Q(new) · K(cached), V(cached)
    ↓
  append new K,V to cache
    ↓
  logits → sample → next token
    ↓
  repeat until EOS
```

## Current Capability
- ✅ 单请求高效 decode（O(n) per step vs O(n²)）
- ✅ Prefill/Decode 阶段分离
- ✅ 连续内存 KV cache

## Current Limitation
- ❌ Cache 无法管理多个请求（一个 KVCache 绑定一个序列）
- ❌ 连续内存导致：(1) 无法提前分配上限空间；(2) 释放后产生碎片
- ❌ 无 Block 抽象
- ❌ 无 Paging 机制
- ❌ 无 Request 对象
- ❌ 无 Batch 支持

## Next Stage
Runtime 目前只能处理一个隐含的 prompt，需要引入 Request 对象来管理请求 ID、状态和生命周期。Commit 004 引入 Request。
