# C119: CUDA graph capture/replay — decode hot path

## Goal

Add CUDA graph capture/replay to `GPUModelRunner.execute_model` for decode-only steps, following the nano-vllm pattern. Aligned with `vllm/vllm/v1/worker/gpu/cudagraph_utils.py` (single-KV-group, no CP, no spec-decode). Disabled by default (`enforce_eager=True`) to keep current eager behavior; toggled by `VllmConfig.model_config.enforce_eager`.

## New Features

### `ModelConfig.enforce_eager`

```python
@dataclass
class ModelConfig:
    ...
    enforce_eager: bool = True
```

Mirrors `vllm/vllm/config/model.py:ModelConfig.enforce_eager`. When False, the runner captures CUDA graphs at `load_model()` time.

### `GPUModelRunner.capture_cudagraph`

Mirrors nano-vllm `ModelRunner.capture_cudagraph` and `vllm v1/worker/gpu/cudagraph_utils.py:cudagraph_capture`.

- Pre-allocates pinned input buffers: `input_ids [max_bs]`, `positions [max_bs]`, `slot_mapping [max_bs]`, `seq_lens [max_bs]`, `block_tables [max_bs, max_num_blocks]`, `query_start_loc [max_bs + 1]`, `outputs [max_bs, hidden_size]`.
- Ladder of captured batch sizes: `[1, 2, 4, 8, 16, 32, ..., max_bs]`.
- For each `bs` (in reverse), does a warmup `model(input_ids, positions)` then captures via `torch.cuda.graph(graph, self.graph_pool)`. Shares a `graph_pool` across sizes (memory reuse).
- Causal=False in the captured attention metadata (decode queries don't need a causal mask).

### `GPUModelRunner._run_with_cudagraph`

Mirrors nano-vllm `ModelRunner.run_model` decode path:

```python
gv["input_ids"][:bs]   = input_batch.input_ids
gv["positions"][:bs]   = input_batch.positions
gv["slot_mapping"].fill_(-1)
gv["slot_mapping"][:bs] = input_batch.slot_mapping
gv["seq_lens"].fill_(0)
gv["seq_lens"][:bs]    = input_batch.seq_lens
gv["block_tables"][:bs, :bt_width] = input_batch.block_table
gv["query_start_loc"][:bs+1] = arange(1, bs+1)  # decode: each req is 1 token
graph.replay()
return gv["outputs"][:bs]
```

### `execute_model` graph dispatch

Decode-only steps replay a captured graph when all of these hold:

```python
can_use_graph = (
    not self.enforce_eager
    and self.graph_vars is not None
    and not scheduler_output.scheduled_new_reqs        # no prefill
    and input_batch.num_reqs <= self._max_num_reqs
    and (input_batch.query_start_loc[1:] - input_batch.query_start_loc[:-1]).max() == 1
)
```

Prefill or non-decode steps fall back to eager (set_forward_context + model.forward).

## Runtime Flow

```
execute_model(scheduler_output)
  ├─ _update_states
  ├─ _prepare_inputs → InputBatch
  ├─ can_use_graph? (decode-only, enforce_eager=False, bs ≤ max)
  │    └─ _run_with_cudagraph:
  │         ├─ gv[input_ids][:bs] = input_batch.input_ids
  │         ├─ gv[positions][:bs] = input_batch.positions
  │         ├─ gv[slot_mapping].fill_(-1); gv[slot_mapping][:bs] = ...
  │         ├─ gv[seq_lens][:bs] = input_batch.seq_lens
  │         ├─ gv[block_tables][:bs, :width] = input_batch.block_table
  │         ├─ graph.replay()
  │         └─ return gv[outputs][:bs]
  └─ else: set_forward_context + self.model(input_ids, positions)
  ├─ _sample
  └─ _postprocess
```

## Current Capability

- `python run.py` with default `enforce_eager=True`: identical 50-token output to C118.
- `enforce_eager=False`: same tokens emitted for the first 10 tokens (verified by overriding `ModelConfig.enforce_eager`). Decode-only steps replay captured graphs; prefill steps still run eagerly.
- 191 passed / 55 failed — same baseline as C118.
- Decode CUDA graph replay path is exercised end-to-end (input copy → graph.replay → sample → postprocess).

## Current Limitation

- `enforce_eager` is a per-`ModelConfig` flag, not a per-step flag. Switching it requires recreating the runner.
- The captured graph assumes `causal=False` (single-token queries). Multi-token decode (speculative decoding) is not captured — falls through to eager. Mirrors nano-vllm's branch (`input_ids.size(0) > 512 or is_prefill or enforce_eager` → eager).
- Only `input_ids`, `positions`, `slot_mapping`, `seq_lens`, `block_tables`, `query_start_loc` are pinned graph buffers. Adding new per-batch buffers requires re-capture.
- The captured graph uses the model's actual `block_table` stride for the per-layer attention. If the attention backend changes (e.g., FA3 vs Triton), the captured graph must be re-captured — not auto-handled here.
- `static_forward_context` registration (where `Attention.__init__` would register each layer name) is not yet wired; the captured graph's `set_forward_context(attn_dict)` re-creates the dict each replay. Same shape as eager path.
