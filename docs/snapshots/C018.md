# C018: Physical KV Cache Runtime

## Goal

Replace simple `KVCacheBlock` / `BlockPool` with enhanced block management:
FreeKVCacheBlockQueue (LRU eviction), ref_cnt, block_hash, and
`allocate_slots()` interface.  KVCacheManager no longer creates
KVCache (HF past_key_values) objects — it's a pure resource manager.

## New Features

- `v1/core/kv_cache_utils.py` — enhanced KVCacheBlock (+ref_cnt, block_hash,
  doubly-linked list pointers) + FreeKVCacheBlockQueue (O(1) LRU alloc/free)
- `v1/core/block_pool.py` — enhanced BlockPool with FreeKVCacheBlockQueue,
  cached_block_hash_to_block, touch(), evict_blocks(), get_cached_block()
- `v1/core/kv_cache_manager.py` — allocate_slots() interface + KVCacheBlocks,
  no longer creates KVCache (HF past_kv) objects
- `v1/kv_cache_interface.py` — KVCacheSpec as Attention↔KVCacheManager boundary
- Scheduler uses allocate_slots() instead of allocate()
- EngineCore imports from v1/core/ paths
- Old cache/ files → bridge imports

## Runtime Flow

```
Scheduler.schedule()
  └── KVCacheManager.allocate_slots(req, num_tokens) → KVCacheBlocks | None
        └── BlockPool.get_new_blocks(n) → list[KVCacheBlock]
              └── FreeKVCacheBlockQueue.popleft_n(n)

EngineCore.step()
  └── model_output = executor.execute_model(scheduler_output)
  └── on finish: KVCacheManager.free(rid)
        └── BlockPool.free_blocks(blocks)
```
