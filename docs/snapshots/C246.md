# C246 — Scheduler 资源感知 (KV-aware scheduling)

> Closes the A-level "Scheduler 资源感知 (KV-aware)" gap from
> `phase3-distributed-runtime-plan.md` § Phase 3.
>
> Opt-in `kv_aware` flag + per-request KV budget estimation + occupancy
> ceiling check that runs before `allocate_slots`, avoiding the
> wasted-prefill-then-preempt cycle.

## Goal

Add a pre-flight check to the scheduler that estimates a candidate
request's KV cost and rejects it (by requeuing) before the
`allocate_slots` call, when the cost would push KV occupancy over a
configured ceiling.  When `kv_aware=False` (default), the legacy
allocation-fail path is preserved.

Specific deliverables:

1. `SchedulerConfig.kv_aware: bool = False` + `kv_occupancy_threshold:
   float = 0.95` (opt-in flags).
2. `Scheduler._estimate_kv_blocks_for_request(request) -> int` —
   ceil((prompt_len + max_output) / block_size), with safe
   fallbacks for missing `sampling_params` and zero-length prompts.
3. `Scheduler._kv_blocks_in_use()` / `_total_kv_blocks()` /
   `_kv_budget_ceiling()` — occupancy tracking helpers.
4. `Scheduler._has_kv_budget_estimate(request) -> bool` — the pre-
   flight check (returns True for `kv_aware=False` to preserve the
   legacy path).
5. `_pull_new_requests` integration — pre-flight check sits between
   the LoRA budget check and the `allocate_slots` call.

The new pre-flight check sits between LoRA budgeting and KV
allocation — the order matters because LoRA decisions can fail on
either side independently.

## Current Capability

* **`kv_aware` flag** — opt-in cost-aware scheduling.
* **`kv_occupancy_threshold`** — operator-tunable ceiling (default
  0.95 = 5% headroom).
* **Per-request KV budget estimation** — `ceil((prompt + max_output)
  / block_size)`, with safe fallbacks for zero prompts / missing
  sampling params.
* **Occupancy tracking** — `_kv_blocks_in_use` + `_total_kv_blocks`
  + `_kv_budget_ceiling` helpers exposed for ops + tests.
* **Pre-flight check** — `_has_kv_budget_estimate` short-circuits
  over-ceiling requests without the wasted prefill cycle.
* **Backwards-compatible** — `kv_aware=False` preserves the legacy
  allocation-fail path; existing tests pass unchanged.
* **AsyncScheduler inheritance** — `AsyncScheduler` (C245) inherits
  the `kv_aware` flag and the budget helpers via the standard
  `super().__init__` chain.
* **29 tests** across 7 classes covering config defaults + math +
  occupancy tracking + pre-flight decisions + pull-path integration.

## Current Limitation

* **No multimodal encoder budget** — vLLM has a separate
  `MultiModalBudget` for encoder compute + cache; my-vllm doesn't
  ship multimodal models so this is out of scope.
* **No adaptive threshold** — the ceiling is a static configuration
  knob; future work could adjust it based on observed preemption rate.
* **No per-tenant thresholds** — single global threshold; multi-
  tenant isolation (C260) would extend this.
* **No interaction with preemption priority** — when the ceiling is
  hit and KV-aware skips the request, it doesn't trigger a preempt
  (that's the legacy path's job).  C260 will combine kv_aware +
  priority-aware preemption.
