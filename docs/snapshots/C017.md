# C017: Execution Batch Framework

## Goal

Replace per-request `_prefill` / `_decode_step` loops in EngineCore with
a single `executor.execute_model(SchedulerOutput)` call.  Prefill is
batched across all new requests in one model forward.

## New Features

- `v1/worker/worker_base.py` — `execute_model(SchedulerOutput)` abstract method
- `v1/worker/gpu_worker.py` — Worker delegates to GPUModelRunner
- `v1/worker/gpu_model_runner.py` — GPUModelRunner with batch prefill + per-request decode
- `v1/worker/gpu/input_batch.py` — InputBatch dataclass (C019/C022 extensions)
- `v1/executor/abstract.py` — Executor ABC with execute_model()
- `v1/executor/uniproc_executor.py` — UniProcExecutor with execute_model()
- EngineCore.step() simplified to: schedule → execute_model → process output
- Batch prefill: all new requests stacked into one model forward (padding handled)
- 3-request generation: 0.34s total (0.11s/req) vs ~0.5s per-request before

## Runtime Flow

```
EngineCore.step()
  │
  ├── scheduler_output = scheduler.schedule()        ← SchedulerOutput
  │
  ├── model_output = executor.execute_model(scheduler_output)
  │   └── Worker → GPUModelRunner.execute_model()
  │       ├── _prefill_batch(new_datas)  ← 1 model forward (padded)
  │       └── for each running req: _decode_one()  ← per-request (HF KV)
  │
  └── for each (req_id, tokens) in model_output:
        check EOS → finish / update
```
