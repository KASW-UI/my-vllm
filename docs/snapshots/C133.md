## What C133 did

### 1. `v1/core/kv_connector.py` → `distributed/.../v1/base.py` (migration)

The new `base.py` contains **13 types** (was 6 in the old file):

**Migrated from the old file (6):**
- `KVTransferMethod` — enum (SHARED_MEMORY / NCCL / RDMA)
- `TransferStatus` — enum (SUCCESS / TIMEOUT / CORRUPTION)
- `TransferBundle` — dataclass (per-request transfer payload)
- `RecvResult` — dataclass (consumer-side check_transfer_done result)
- `KVConnectorBase_V1` — ABC with the runtime interface
- `NoopConnector` — concrete no-op implementation

**Newly added to match vLLM's `__init__.py` (7):**
- `CopyBlocksOp` — `Callable` type alias for host↔device copy ops
- `KVConnectorRole` — enum (SCHEDULER / WORKER)
- `KVConnectorHandshakeMetadata` — ABC (P/D handshake metadata)
- `KVConnectorMetadata` — ABC (Scheduler → Worker metadata)
- `KVConnectorWorkerMetadata` — ABC with abstract `aggregate()`
- `SupportsHMA` — ABC for hybrid memory allocator support
- `supports_hma` — detection helper

These 7 names were already imported by `__init__.py` (and silently
broken since the file was empty). C133 fills in the missing types
so the existing import chain now works.

**Constructor signature change:**

`KVConnectorBase_V1.__init__` now defaults to `(vllm_config=None,
role=None, kv_cache_config=None)` instead of `()` so the existing
`NoopConnector()` call site in `EngineCore._kv_connector_init` can
still construct without ceremony while new call sites can pass the
vLLM-canonical `(vllm_config, role, kv_cache_config)` triplet.

`NoopConnector` now calls `super().__init__(vllm_config, role,
kv_cache_config)` to forward the args.

### 2. New `factory.py` — `KVConnectorFactory`

Mirrors `vllm/distributed/kv_transfer/kv_connector/factory.py:1`.
Provides:

- `KVConnectorFactory.register_connector(name, module_path, class_name)`
  (lazy-loading via `importlib.import_module`).
- `KVConnectorFactory.get_connector_class_by_name(name)` — raise
  `ValueError` if unknown.
- `KVConnectorFactory.get_connector_class(kv_transfer_config)` —
  resolver from `KVTransferConfig.kv_connector`.
- `KVConnectorFactory.create_connector(vllm_config, role,
  kv_cache_config=None)` — top-level factory; mirrors vLLM's
  HMA-gate check (present but no-op in my-vllm since HMA is not yet
  enabled).

**Registered connectors:** `NixlConnector` only. vLLM registers ~14;
my-vllm's career-relevant subset (PD disaggregation via shared-memory
NIXL local backend) needs only this one. Adding more = one extra
`register_connector` call.

### 3. `nixl/connector.py` — vLLM-aligned constructor signature

`NixlConnector.__init__` now takes `(vllm_config, role,
kv_cache_config=None, num_layers=None, buffer_size=None)` matching
vLLM's `KVConnectorBase_V1` signature. The optional `num_layers` /
`buffer_size` kwargs are preserved for the local shared-memory
implementation's buffer tuning; they default to `12` layers and
`100MB` per layer.

### 4. `v1/engine/core.py` — 3 import paths + connector init args

- L36: `from my_vllm.v1.core.kv_connector import TransferBundle` →
  `from my_vllm.distributed.kv_transfer.kv_connector.v1 import TransferBundle`
- L52 (TYPE_CHECKING): same change for `KVConnectorBase_V1`
- L428–433: `_kv_connector_init()` now imports `KVConnectorRole` +
  `NoopConnector` from the new location and constructs
  `NoopConnector(self.vllm_config, KVConnectorRole.SCHEDULER)`.

### 5. `nixl/__init__.py` — works as-is

The previously-broken `from ..base import ...` chain now resolves
to the populated `base.py`. No edit needed.
