### 2. Wire-format constants

Preserved byte-for-byte from vLLM:

```python
GET_META_MSG = b"get_meta_msg"
PUSH_REG_NOTIF_PREFIX = b"PUSH_REG:"
NIXL_CONNECTOR_VERSION = 5
```

The `NIXL_CONNECTOR_VERSION` is the wire-format compatibility counter.
Production wire-up to a real NIXL deployment must match this version
exactly to interop with upstream vLLM instances.

### 3. TP rank mapping (full vLLM implementation)

`compute_tp_mapping(transfer_topology, remote_tp_size, group_spec_types)`
is **extracted verbatim** from `vllm/.../tp_mapping.py:65-142`.  Handles:

* **D_TP == P_TP**: each local rank reads from exactly one remote.
* **D_TP > P_TP**: multiple local ranks read different chunks from
  one remote (different KV heads).
* **P_TP > D_TP**: one local rank reads from multiple remote ranks
  (with GQA dedup).
* **MLA**: every rank holds a duplicate, so single remote rank suffices.
* **Hetero-TP** rank_offset_factor: `tp_rank % (D_TP / P_TP)`.
* **MambaSpec (SSM)** per-group source rank splitting.

This is the **most algorithmically rich** piece of the NIXL
connector and has no NIXL runtime dependency.

### 4. Three-class connector facade

Mirrors vLLM's split between pull-mode (consumer issues READ) and
push-mode (producer issues WRITE):

* `NixlBaseConnector` — common logic (save_kv_layer / start_load_kv
  / wait_for_layer_load / wait_for_save / check_transfer_done /
  send_ack / drain_acks / get_num_new_matched_tokens /
  request_finished).  Uses the local shared-memory backend (C131-era)
  for actual KV transfer — production deployments replace the
  save/load paths with NIXL RDMA calls.
* `NixlPullConnector` — extends `NixlBaseConnector`, delegates
  `start_load_kv` to `NixlPullConnectorWorker` (READ-driven).
* `NixlPushConnector` — extends `NixlBaseConnector`, delegates
  `start_load_kv` to `NixlPushConnectorWorker` (WRITE-driven +
  background thread for notif polling).
* `NixlConnector` — backward-compat alias for `NixlPullConnector`.

### 5. Metadata dataclasses + compatibility hash

* `NixlAgentMetadata` — engine's local metadata (engine_id,
  agent_metadata, kv_caches_base_addr, device_id, num_blocks,
  block_lens, kv_cache_layout, block_size, ssm_sizes,
  attn_backend_name, physical_blocks_per_logical_kv_block).
* `NixlHandshakePayload` — two-phase handshake (compatibility_hash
  + agent_metadata_bytes).
* `compute_nixl_compatibility_hash` — SHA-256 of (model name +
  dtype + num_kv_heads + head_size + num_hidden_layers +
  attn_backend + cache_dtype + NIXL connector version + HMA flag).
* `NixlConnectorMetadata` — per-step connector metadata exchanged
  scheduler → worker (``reqs_to_save`` / ``reqs_to_recv`` /
  ``reqs_to_send`` / ``reqs_in_batch`` / ``reqs_not_processed`` /
  ``heartbeat_by_engine`` / ``push_registrations`` /
  ``push_finished_blocks``).
* `HeartbeatInfo` — D-worker → P-worker heartbeat (req_ids, host,
  port, tp_size, pp_size).
* `RemoteMeta` — per-request metadata about the remote producer
  (block_ids, host, port, engine_id, request_id, blocks_expiry_time).
* `ReqMeta` — per-request KV transfer state (local_block_ids,
  local_physical_block_ids, tp_size, remote, remote_block_size,
  pp_size).

### 6. Stats tracking

`NixlKVConnectorStats` + `TransferTelemetry` track:
* `transfer_duration` / `post_duration` — per-transfer wall-clock (seconds).
* `bytes_transferred` / `num_descriptors` — per-transfer wire volume.
* `num_failed_transfers` / `num_failed_notifications` /
  `num_kv_expired_reqs` — failure counters.

`reduce()` returns a CLI-friendly dict (Num successful transfers,
Avg/P90 xfer time, Avg/P90 post time, Avg MB per transfer,
Throughput (MB/s), Avg number of descriptors).

`clone_and_reset()` + `aggregate()` enable periodic logging +
multi-rank aggregation.

### 7. Protocol surface (no NIXL runtime)

`NixlBaseConnectorScheduler` + `NixlBaseConnectorWorker` provide:

* **Scheduler side**:
  - `on_new_request` — register a new prefill request.
  - `add_remote_engine` — store the handshake metadata.
  - `set_xfer_handshake_metadata` — store the local handshake payload.
  - `build_connector_meta` — assemble per-step `NixlConnectorMetadata`.
  - `get_num_new_matched_tokens` — return 0 (skeleton).
  - `update_state_after_alloc` — no-op (skeleton).
  - `request_finished` — cleanup.
  - `shutdown` — release state.

* **Worker side**:
  - `register_kv_caches` — record KV cache references for descriptor building.
  - `add_remote_agent` — store a remote engine's handshake metadata.
  - `_compute_handshake` — build the local handshake payload.
  - `save_kv_to_host` — copy device → host buffer (skeleton).
  - `sync_recved_kv_to_device` — copy host → device (skeleton).
  - `get_finished` — return (done_reqs, failed_reqs) sets.
  - `shutdown` — release state.

### 8. `NIXL_CONNECTOR_VERSION = 5` — wire-format compat counter

Tracks incompatibilities across:
* `NixlAgentMetadata` schema changes.
* `kv_transfer_params` schema / semantics changes.
* NIXL transfer protocol or wire format changes.
* KV cache memory layout / block organization changes.

Production wire-up to vLLM instances must match this version.

## Runtime Flow

```
                     Producer (Prefill)              Consumer (Decode)
                     ────────────────                ───────────────
handshake            NixlBaseConnector                NixlBaseConnector
                     .add_remote_agent(engine_id,     .add_remote_agent(producer_id,
                     consumer_meta)                    producer_meta)
                     ._compute_handshake() → local_meta

request admit        scheduler.on_new_request(req)    scheduler.on_new_request(req)

per step             scheduler.build_connector_meta    scheduler.build_connector_meta
                     → NixlConnectorMetadata           → NixlConnectorMetadata
                     .reqs_to_save[req_id] = ReqMeta   .reqs_to_recv[req_id] = ReqMeta

prefill              worker.save_kv_layer(layer, kv)
                     → host buffer (local: shared mem)
                     → NIXL WRITE xfer (production)

load                 worker.wait_for_layer_load(layer)
                     → NIXL READ xfer poll (production)
                     → host → device copy

finish               request_finished(req)             request_finished(req)
                     scheduler.shutdown()              worker.shutdown()
```

## Current Capability

* **Full 13-file NIXL package** — mirrors vLLM's package structure.
* **Wire-format compat** — constants + dataclass schemas match vLLM
  byte-for-byte.
* **TP mapping math** — extracted verbatim from vLLM (pure Python,
  no NIXL runtime); handles D_TP/P_TP combinations, MLA, GQA dedup,
  MambaSpec per-group splitting.
* **Three-class connector** — Base / Pull / Push variants;
  backward-compat `NixlConnector` alias for `NixlPullConnector`.
* **Local shared-memory backend** — preserves the C131/C133-era
  functionality so the connector is exercisable in dev / single-process
  tests without RDMA hardware.
* **Stats tracking** — per-transfer timing + byte counts +
  failure counters + CLI reduce().
* **C212 regression-clean** — `ExampleConnector` (subclass of
  `NixlConnector`) still works with `num_layers` + `buffer_size`
  kwargs.

## Current Limitation

1. **No NIXL runtime** — the actual RDMA backend is not vendored.
   `compute_handshake` uses a JSON placeholder for the NIXL agent
   descriptor; `save_kv_to_host` / `sync_recved_kv_to_device` are
   skeletons; `_nixl_agent` is `None`.
2. **No Prometheus metrics** — `NixlPromMetrics` is omitted (my-vllm
   has no Prometheus integration).
3. **No ZMQ handshake listener** — `zmq_ctx` is omitted (ZMQ not
   vendored).  The C242 SHM broadcast primitive is the substitute.
4. **No HMA / MambaSpec** — `_build_mamba_local` / `_build_mamba_remote`
   are stubbed (my-vllm has no SSM model support).
5. **No block descriptor computation** — the 600+ lines of NIXL
   tensor-descriptor math (`_build_local_splits_from_plan`,
   `_fa_desc_replicated`, `_build_fa_local`, `_build_fa_remote`,
   `_stack_descs`, `_register_packed_kv_cache`) are stubbed.
6. **No background threads** — `nixl-push-writer` and heartbeat
   listener are deferred to C251.
