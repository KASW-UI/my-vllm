# C014: Production Runtime

## Goal
C013 的研究用 runtime 无法服务外部请求。本阶段添加 API 服务器和公 API，实现从"研究代码"到"可服务系统"的转变。C014 之后不再新增核心架构。

## New Features
- `engine/llm_engine.py` — `LLMEngine`：外部公 API，封装 StateManager
- `server/api_server.py` — OpenAI 兼容 `/v1/completions`（stdlib http.server，零依赖）
- `server/async_llm.py` — `AsyncLLM`：asyncio 异步包装
- `metrics/collector.py` — `MetricsCollector`：请求数、延迟、吞吐量
- 新增 `examples/server.py`

## Runtime Flow
```
Client: POST /v1/completions {"prompt": "...", "max_tokens": 50}
  │
  ├─ CompletionHandler.do_POST()
  ├─ LLMEngine.generate(prompt, max_new_tokens)
  │     ├─ add_request(prompt) → Request(WAITING)
  │     ├─ while has_work(): step()
  │     │     ├─ scheduler.schedule()    → promote waiting→running
  │     │     ├─ worker.execute_prefill() → model forward
  │     │     ├─ worker.execute_decode()  → model forward
  │     │     └─ scheduler.finish()       → cleanup
  │     └─ return {text, finish_reason, usage}
  │
  └─ 200 OK {"choices": [{"text": "..."}], "usage": {...}}
```

## C014 Achieves
C014 achieves **architectural parity** with the core execution path of vLLM V1.
The implementation intentionally removes production complexity while preserving:

- EngineCore driven execution loop
- Scheduler → Executor → Worker execution boundary
- KVCacheManager → BlockPool memory abstraction
- Request lifecycle management (WAITING → RUNNING → FINISHED)
- OpenAI-compatible API server
