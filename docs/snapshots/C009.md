# C009: Paged KV Cache

## Goal
C008 的连续 KV cache 释放后产生碎片——无法被其他 request 复用。本阶段引入 Paged KV Cache，将 KV cache 划分为固定大小 Block，通过 BlockPool 统一分配/回收，消除碎片。

## New Features
- `cache/block.py` — `KVCacheBlock`：固定大小 KV cache 块
- `cache/block_pool.py` — `BlockPool`：块池，自由块队列管理
- `cache/block_table.py` — `BlockTable`：per-request 逻辑→物理块映射
- `KVCacheManager` 重构：`allocate()` 通过 BlockPool 分配块，`free()` 归还块
- `allocator.py` 被 BlockPool 替代

## Runtime Flow
```
Before (C008 — continuous, fragmented):
  BlockPool (logical)
    ┌──┬──┬──┬──┬──┬──┬──┬──┐
    │A0│A1│B0│B1│  │  │  │  │  A free → gaps!
    └──┴──┴──┴──┴──┴──┴──┴──┘
          ▲       ▲
    holes cannot be reused

After (C009 — paged, no fragmentation):
  BlockPool (physical)
    ┌──┬──┬──┬──┬──┬──┬──┬──┐
    │A0│A1│B0│B1│F0│F1│F2│F3│  Free blocks always ready
    └──┴──┴──┴──┴──┴──┴──┴──┘
                    ▲ ▲ ▲ ▲
                  any-block reusable

BlockTable (per-request logical→physical):
  Request A: [0, 1]     → stores tokens 0-15, 16-31
  Request B: [2, 3]     → stores tokens 0-15, 16-31
  Request C: [4, 5, 6]  → needs 3 blocks
```

## Allocation Flow
```
KVCacheManager.allocate(request)
  │
  ├─ num_tokens = len(prompt_token_ids)
  ├─ num_blocks = ceil(num_tokens / block_size)
  │
  ├─ BlockPool.get_new_blocks(num_blocks)
  │     ├─ if free < num: return None  → Scheduler stops promoting
  │     └─ pop from free_ids, mark !is_free, return blocks
  │
  ├─ BlockTable(block_size) → append(blocks)
  └─ create KVCache
```

## Current Capability
- ✅ 固定大小 block 分配（消除碎片）
- ✅ BlockPool 统一管理（自由块复用）
- ✅ BlockTable per-request 映射
- ✅ Scheduler 感知 block 可用量

## Current Limitation
- ❌ Block 仅是逻辑概念——实际 attention 仍用 HF 连续 `past_key_values`
- ❌ 无自定义 attention kernel（PagedAttention）
- ❌ Decode 阶段未按需分配新 block（预分配全部 prompt blocks）
- ❌ 无 prefix caching（block hash 查找）
