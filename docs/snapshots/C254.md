# C254 — KV Cache Coordinator 多 spec 协商

## Goal

Closes the A-level "KV Cache Coordinator 多 spec 协商" gap from
`phase3-distributed-runtime-plan.md`.  Phase 4 v2 progress: 5/10
commits closed.

OPT is Dense so my-vllm only ever exercises `FullAttentionSpec` →
`FullAttentionManager` end-to-end today. The point of C254 is to
build the **multi-spec routing surface** so future Llama
(GQA/SWA), DeepSeek (MLA/Mamba), and hybrid-model integration
just plugs into the registry instead of rewriting the coordinator.

## New Features

### 1. `KVCacheSpec` hierarchy + `KVCacheConfig` (NEW + EXTENDED)

`my_vllm/v1/kv_cache_interface.py` (EXTENDED, ~325 lines, was 15):

* **`KVCacheSpec` (frozen dataclass)** — abstract base carrying
  `block_size` + `page_size_bytes` / `storage_block_size` /
  `max_memory_usage_bytes` / `max_num_blocks_per_req` /
  `is_uniform_with_collection` (registry-walk).
* **`AttentionSpec(KVCacheSpec)`** — carries `num_kv_heads`,
  `head_size`, `dtype`, `kv_quant_mode`, `page_size_padded`.
  Computes `real_page_size_bytes` (with per-token-head scale
  budget) and `page_size_bytes` (with alignment padding).
* **`FullAttentionSpec(AttentionSpec)`** — **the only concrete
  subclass actually exercised in my-vllm today**. Mirrors
  vLLM V1 `vllm/v1/kv_cache_interface.py:FullAttentionSpec`
  with the per-layer geometry + `sliding_window` /
  `attention_chunk_size` / `non_causal` carrier fields.
* **`KVCacheSpecKind` (str-enum)** — discriminator for hybrid
  dispatch (`FULL_ATTENTION`, `SLIDING_WINDOW`,
  `CHUNKED_LOCAL_ATTENTION`, `MAMBA`, `CROSS_ATTENTION`,
  `UNKNOWN`).
* **`KVCacheTensor` / `KVCacheGroupSpec` / `KVCacheConfig`** —
  the per-model config consumed by `KVCacheCoordinator`.
  `KVCacheConfig.needs_kv_cache_zeroing` reports whether
  freshly allocated blocks must be zeroed (Mamba + mixed-
  precision caches).
* **`get_kv_cache_spec_kind(spec)`** — subclass-aware kind
  dispatch (FullAttentionSpec → FULL_ATTENTION; shell managers
  → their kind via the registry; unknown → UNKNOWN).

`KVQuantMode` enum (pre-existing from C213) gains `FP8_TENSOR = 1`
restored (the integer value used by the C211/C213 quantization
kernels).

### 2. `KVCacheSpecRegistry` (NEW)

`my_vllm/v1/kv_cache_spec_registry.py` (NEW, ~165 lines):

* `KVCacheSpecMetadata` — frozen dataclass recording the
  registered spec class + manager class + uniform-type base.
* `KVCacheSpecRegistry` — global singleton with:
  - `register(spec_cls, manager_class, uniform_type_base_spec=None)`
    — one-shot per process, idempotent on same metadata, hard
    error on conflicting metadata.
  - `get_manager_class(spec)` — `__mro__` walk, returns the
    closest registered ancestor's manager class.
  - `get_uniform_type_base_spec(spec)` — same `__mro__` walk.
  - `check_kv_cache_spec_registry(specs)` — raises `ValueError`
    on unregistered layer specs.
  - `reset()` — test helper.
* `register_kv_cache_spec(manager_class, uniform_type_base_spec)`
  decorator — the convenient registration form for custom
  subclasses.
* `_ensure_default_registered()` — lazily bootstraps the default
  `FullAttentionSpec` → `FullAttentionManager` registration to
  break the circular import cycle between registry /
  kv_cache_interface / single_type_kv_cache_manager.

### 3. `SingleTypeKVCacheManager` full vLLM surface (EXTENDED)

`my_vllm/v1/core/single_type_kv_cache_manager.py` (EXTENDED,
~1080 lines, was 295):

* New constructor fields: `kv_cache_spec`, `scheduler_block_size`,
  `dcp_world_size`, `pcp_world_size`, `needs_kv_cache_zeroing`,
  `max_admission_blocks_per_request`. New state fields:
  `num_cached_block`, `use_eagle`, `_partial_hit_reqs`,
  `_pending_cow_copies`, `_null_block`, `new_block_ids`.
* **New vLLM-signature methods** (returning list / dispatching to
  the registry):
  - `find_longest_cache_hit(block_hashes, max_length,
    kv_cache_group_ids, block_pool, kv_cache_spec,
    drop_eagle_block, alignment_tokens, ...)` — classmethod.
  - `add_local_computed_blocks(request_id, new_computed_blocks,
    num_local_computed_tokens, num_external_computed_tokens)` —
    two-phase protocol #33775.
  - `allocate_external_computed_blocks(request_id, ...)` — phase 2.
  - `allocate_new_blocks(request_id, num_tokens,
    num_tokens_main_model) -> list[KVCacheBlock]` — vLLM
    signature, returns list.
  - `get_num_blocks_to_allocate(request_id, num_tokens,
    new_computed_blocks, total_computed_tokens,
    num_local_computed_tokens, num_tokens_main_model,
    apply_admission_cap=False) -> int` — vLLM signature.
  - `get_num_common_prefix_blocks(running_request_id) -> int` —
    abstract (subclasses implement).
  - `remove_skipped_blocks(request_id, processed_computed_tokens,
    num_prompt_tokens=None)` — default impl (no-op for full).
  - `new_step_starts()` — step-boundary hook (no-op default).
  - `get_blocks(request_id) -> list[KVCacheBlock]`.
  - `cache_blocks(request, num_tokens, retention_interval=None)` —
    same name, now accepts the retention knob.
  - `_apply_cow(request_id, block_idx, source_block, cow_block)` —
    CoW redirect for partial prefix hits.
  - `take_new_block_ids()` / `take_pending_cow_copies()` /
    `records_new_block_ids` — KV-cache-zeroing bookkeeping.
  - `reachable_block_mask(...)` classmethod — per-block cache
    mask (None = cache all; SWA overrides to skip).
* `FullAttentionManager.find_longest_cache_hit` — real two-phase
  implementation: walks `block_hashes` looking up each in the
  pool; on miss, breaks the chain; for EAGLE, drops one block
  from the hit length; rounds down to the alignment.
* `FullAttentionManager.get_num_common_prefix_blocks` — ref-count
  based detection (a block is "common" iff `ref_cnt ==
  num_running_requests`).
* `get_manager_for_kv_cache_spec(spec, block_pool, ...)` —
  registry lookup + constructor dispatcher.
* `register_all_kvcache_specs()` — one-shot registration of all
  built-in spec/manager pairs (real `FullAttentionSpec` →
  `FullAttentionManager` + shells for SWA / ChunkedLocal / Mamba /
  CrossAttention / MLA).
* **Legacy C134 API preserved** as `_simple` wrappers
  (`get_num_blocks_to_allocate_simple`, `allocate_new_blocks_simple`,
  `cache_blocks_simple`, `_apply_cow_simple`) — the existing
  `UnitaryKVCacheCoordinator` (C134) and `KVCacheManager`
  (C018/C143) continue to work unchanged.

#### Spec / manager shells (C254)

SlidingWindowSpec / ChunkedLocalAttentionSpec / MambaSpec /
CrossAttentionSpec / MLAAttentionSpec + SlidingWindowManager /
ChunkedLocalAttentionManager / MambaManager / CrossAttentionManager
are declared as **class shells** with the vLLM field/method names,
registered in the registry, and raise `NotImplementedError` on
actual cache-hit lookup (sliding-window / Mamba math requires
non-Dense models which are Delete-tier per `docs/alignment-plan.md`).
Adding the real bodies happens when Llama (Phase 5 C260+) or
DeepSeek (Phase 5 C266) lands.

### 4. `KVCacheCoordinator` hierarchy + factory (NEW)

`my_vllm/v1/core/kv_cache_coordinator.py` (EXTENDED, ~915 lines,
was 216):

The new multi-spec coordinator surface — operates on a
`KVCacheConfig` and a `single_type_managers` tuple (one manager
per group, dispatched via the registry):

* **`KVCacheCoordinator` (ABC)** — base class. Builds the
  `single_type_managers` tuple via `get_manager_for_kv_cache_spec`.
  Surface:
  - `get_num_blocks_to_allocate` (full vLLM signature)
  - `allocate_new_computed_blocks` (two-phase protocol #33775)
  - `allocate_new_blocks` (returns per-group block-list tuple)
  - `cache_blocks` / `free` / `pop_blocks_for_free`
  - `get_num_common_prefix_blocks` (per-group list)
  - `remove_skipped_blocks`
  - `get_blocks` (per-group tuple)
  - `new_step_starts`
  - `find_longest_cache_hit` (abstract — subclasses encode the
    cross-group reconciliation strategy)
* **`KVCacheCoordinatorNoPrefixCache(KVCacheCoordinator)`** —
  used when caching is disabled. Returns empty hit regardless
  of input.
* **`UnitaryKVCacheCoordinatorFull(KVCacheCoordinator)`** —
  single-group variant (the production case for Dense models).
  Delegates to the underlying manager's `find_longest_cache_hit`.
* **`HybridKVCacheCoordinator(KVCacheCoordinator)`** — multi-
  group variant. Implements the **fixed-point iteration** from
  vLLM: each attention type either accepts the current candidate
  length or reduces it; on any reduction, restart over all types.
  Converges monotonically. Builds `SpecGroup`s (groups sharing a
  spec merge into one lookup unit) via `verify_and_split_kv_cache_groups`.
* **`SpecGroup` (NamedTuple)** — `(spec, group_ids, manager_cls,
  use_eagle)`. Members sharing a spec are looked up jointly.
* **`get_kv_cache_coordinator(...)` factory** — dispatches to
  `KVCacheCoordinatorNoPrefixCache` / `UnitaryKVCacheCoordinatorFull`
  / `HybridKVCacheCoordinator` based on caching + group count.

The **legacy C134** `UnitaryKVCacheCoordinator` (the simple
single-manager wrapper) lives at the bottom of the same file and
is what `KVCacheManager` consumes today. C254 keeps it untouched
for backward compat.

### 5. `BlockPool.null_block` (EXTENDED)

`my_vllm/v1/core/block_pool.py` gains a `null_block` sentinel:
a synthetic `KVCacheBlock(block_id=-1)` with `is_null=True`,
identity-unique (`is null_block` / `== null_block`), never freed.

C254 deviation from vLLM (L190): we do **not** pop a real block
from the pool for the null_block — vLLM does, but my-vllm's
C008/C018 tests expect block IDs to start at 0 with no offset.
The sentinel is sufficient for SWA / Mamba padding without
disrupting existing pool accounting.

## Runtime Flow (multi-spec coordinator)

```
                              VllmConfig
                                  │
                                  ▼
              KVCacheConfig  (num_blocks, kv_cache_groups)
                                  │
                                  ▼
                   get_kv_cache_coordinator(factory)
                                  │
        ┌─────────────────────────┼────────────────────────────┐
        ▼                         ▼                            ▼
KVCacheCoordinatorNoPrefixCache UnitaryKVCacheCoordinatorFull HybridKVCacheCoordinator
   (caching off)                  (single group)              (≥ 2 groups)
        │                              │                            │
        ▼                              ▼                            ▼
                       single_type_managers = tuple(
                           get_manager_for_kv_cache_spec(...)
                       )
                                  │
                                  ▼
                  FullAttentionManager / SlidingWindowManager / …
                                  │
                                  ▼
                          BlockPool (single source of truth)
```

The legacy `KVCacheManager → UnitaryKVCacheCoordinator` (C134)
path continues to work unchanged; C254 adds the multi-spec
surface alongside it. Phase 5 (C260+) will wire the new
coordinator into `KVCacheManager` once a non-Dense model lands.

## Current Limitation

* `KVCacheManager` still routes through the legacy
  `UnitaryKVCacheCoordinator` (C134). Wiring the new multi-spec
  coordinator into `KVCacheManager` is **deferred to Phase 5**
  — when Llama (GQA/SWA), DeepSeek (MLA/Mamba), or hybrid lands,
  the coordinator switches to `get_kv_cache_coordinator` factory
  output.
* Spec / manager shells (SlidingWindow / ChunkedLocal / Mamba /
  CrossAttention / MLA) raise `NotImplementedError` on actual
  cache-hit lookup. Their real bodies ship with Phase 5 (C260+
  Llama + C266 MLA).
* `MLAAttentionSpec` inherits from `FullAttentionSpec` so the
  registry can route it via `FullAttentionManager` (placeholder);
  Phase 5 C266 ships the real MLA math (`real_page_size_bytes`
  with the 656-byte kv_lora layout).
* `KVCacheConfig.has_mamba_layers` detection works via the
  registry's `manager_class.__name__ == "MambaManager"`; if a
  future spec registers its manager with a different name the
  detection must be updated.
* `Hash block_size` ≠ `block_size` (fine-grained hash within a
  cache block) is supported by the registry surface but not
  exercised by my-vllm yet — `UnitaryKVCacheCoordinatorFull`
  asserts `hash_block_size == block_size`. Phase 5 lifts the
  assertion when MLA / DCP land.
