# C022: Attention Backend Interface

## Goal

Replace direct HF model attention calls with a pluggable
AttentionBackend abstraction, following vLLM V1's
`v1/attention/backend.py` pattern.

## New Features

- `v1/attention/backend.py` — `AttentionBackend` ABC factory:
  `get_name()`, `get_impl_cls()`, `get_kv_cache_shape()`.
  `AttentionImpl` ABC: `forward(query, key, value, kv_cache,
  attn_metadata, output)` — single interface replacing
  `prefill()` / `decode()` split.
- `v1/attention/metadata.py` — `CommonAttentionMetadata`
  dataclass, assembling fields from prior commits:
  - C017 InputBatch → `query_start_loc`, `seq_lens`, `positions`
  - C019 BlockTables → `block_table_tensor`, `slot_mapping`
  - C020 RequestState → `num_reqs`, `num_actual_tokens`,
    `max_query_len`, `max_seq_len`
- `v1/attention/selector.py` — `get_attn_backend()` returns
  `TorchAttentionBackend` (no FlashAttention dependency at C022)
- `v1/attention/backends/torch_attn.py` — `TorchAttentionBackend`
  + `TorchAttentionImpl`: default backend using
  `torch.nn.functional.scaled_dot_product_attention` with
  grouping-query attention support
- GPUModelRunner: imports selector + metadata, stores
  `attn_backend_cls`, builds `CommonAttentionMetadata` via
  `_build_attn_metadata()`
- Mirrors vLLM V1 attention interface architecture

## Current Limitation

- `attn_backend_cls` is imported and stored but not yet consumed
  by model forward — HF model is still called directly (with
  `use_cache=True` and padded batch tensors)
- No PagedAttention kernel → C023 PagedAttention Runtime will
  implement actual block table-driven K/V writes and attention
  reads via the AttentionImpl interface
- No FlashAttention hardware backend (requires CUDA extension;
  Torch SDPA is the fallback)
- No reshape_and_cache — KV tensors are NOT written into the
  physical KV cache pool during forward

## Next Stage

C023: PagedAttention Runtime — implements PagedAttention as a
PyTorch operation using the physical KV cache pool, block table
GPU tensor, and slot_mappings.  The model forward loop will call
AttentionImpl.forward() instead of HF attention.
