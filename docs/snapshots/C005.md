# C005: Static Batch

## Goal
C004 一次只能执行一个 request，GPU 利用率低。本阶段引入 Static Batch，允许将多个 request 的 prompt prefill 和 decode 合并为一次 forward，提升 GPU 利用率。

## New Features
- `batch/batch_executor.py` — `BatchExecutor` 静态批处理执行器
- Prefill batch：右 pad 所有 prompt 到 max_len，单次 batch forward
- Decode lockstep：所有 request 每步同时 decode 一个 token
- 完成 request 依然占据 batch 位置直到全部结束
- `LLM.generate_batch()` — 批量推理入口
- `main.py` — 新增 batch 模式

## Runtime Flow
```
Request[]  (N个)
  │
  ▼
┌─────────────────────────────────────────────────────────┐
│  BatchExecutor                                          │
│                                                         │
│  Prefill:                                               │
│  ┌──────────────────────────────────────────────────┐   │
│  │ Req A: ████████████░░░░  (pad to max_len)         │   │
│  │ Req B: ██████░░░░░░░░░░                           │   │
│  │ Req C: ██████████░░░░░░                           │   │
│  └──────────────────────────────────────────────────┘   │
│    ↓ batch forward(model, attention_mask)               │
│    ↓ past_key_values [batch, layers, ...]               │
│                                                         │
│  Decode (lockstep):                                     │
│  ┌──────────────────────────────────────────────────┐   │
│  │ Step 1: [tok_A, tok_B, tok_C] → forward → sample  │   │
│  │ Step 2: [tok_A, tok_B, tok_C] → forward → sample  │   │
│  │ ...                                                │   │
│  │ Step 10: B finishes (EOS) → still in batch!        │   │
│  │ Step 20: all done                                  │   │
│  └──────────────────────────────────────────────────┘   │
└─────────────────────────────────────────────────────────┘
```

## Current Capability
- ✅ 多个 request 同时 forward（GPU 利用率提升）
- ✅ Batch prefill + batch decode
- ✅ 单次 forward 处理多个 request 的 attention

## Current Limitation
- ❌ 静态 batch：短序列完成后依然占据 batch 位置（浪费 GPU）
- ❌ 无动态加入退出——新 request 必须等当前 batch 全部完成
- ❌ Padding 浪费显存和计算
- ❌ 没有 scheduler 控制 batch 构成
- ❌ 每个 request 的 KV cache 生命期与 batch 绑定

## Benchmark
```
3 requests × 30 tokens, opt-125m:
  Batch  total: 1.3x speedup vs 3 singles
```

## Next Stage
静态 batch 无法处理不同生命周期的 request（短 request 完成后浪费 slot，新 request 无法加入）。Commit 006 引入动态状态管理（waiting/running/finished queue）。
