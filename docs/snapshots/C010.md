# C010: ModelRunner

## Goal
C009 的 StateManager 直接操作 model forward 和 sampling，职责过重。本阶段抽离 ModelRunner，封装模型执行细节，同时将执行状态（`_steps`/`_next_token`）从 KVCacheManager 移入 ModelRunner。

## New Features
- `worker/model_runner.py` — `ModelRunner`：封装 forward + sampling
- `ModelRunner.prefill()` — 执行 prefill，返回首个 token
- `ModelRunner.decode()` — 执行一个 decode step，返回下一个 token
- 执行状态（step count / next token）从 KVCacheManager 移入 ModelRunner
- KVCacheManager 简化为纯 block 管理层

## Architecture
```
StateManager.step()
  │
  ├─ scheduler.schedule()    →  "谁运行?"
  │
  ├─ runner.prefill(rid, ids, cache)  →  "怎么跑?"
  │     └─ model forward + greedy_sample
  │
  ├─ runner.decode(rid, cache)        →  "怎么跑?"
  │     └─ model forward + greedy_sample
  │
  └─ kv_cache_manager.free(rid)       →  "释放资源"

C009 → C010 职责变化:
  StateManager   (-) 不再直接调用 model.forward()
  KVCacheManager (-) 移除 _steps / _next_token（不再管执行状态）
  ModelRunner    (+) 封装 forward + sampling + 执行状态
```

## Current Capability
- ✅ ModelRunner 独立封装模型执行
- ✅ 执行状态（steps/next_token）归属正确
- ✅ KVCacheManager 职责收窄为纯 block 分配
- ✅ StateManager 变为纯 orchestrator

## Current Limitation
- ❌ ModelRunner 直接持有 model 引用（无 Worker 隔离层）
- ❌ 无多 GPU 支持（Tensor Parallel）
- ❌ 无 Executor 抽象

## Next Stage
Model 需要独立于 engine 进程。Commit 011 引入 Worker，将 model 初始化和设备管理封装在 Worker 层。
