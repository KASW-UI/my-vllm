# C007: Scheduler

## Goal
C006 的 StateManager 职责膨胀——同时管理队列、执行 forward、处理状态转换：
```
StateManager
├── waiting/running queues
├── prefill/forward 执行
├── KV cache 管理
└── 调度策略 (FCFS, max_running)
```
本阶段将调度逻辑抽离为独立的 Scheduler 组件。

## New Features
- `scheduler/scheduler.py` — 独立 Scheduler（FCFS + max batch size）
- `Scheduler.schedule()` — 从 waiting 队列中按 FCFS 提升到 running
- `Scheduler.finish()` — 移除已完成的 request
- `Scheduler.add_request()` — 向 waiting 队列添加请求
- `StateManager` 重构：调度委托给 Scheduler，仅负责执行

## Runtime Flow
```
StateManager.step()
  │
  ├─ scheduler.schedule()          ← "谁该运行？"
  │     ├─ FCFS: waiting.pop(0)
  │     ├─ max_running 上限
  │     └─ return [newly_promoted]
  │
  ├─ _prefill(new_requests)        ← "怎么执行？"
  │     ├─ KVCache.prefill()
  │     ├─ greedy_sample → first token
  │     └─ store KV cache
  │
  ├─ _decode_step(all_running)     ← "怎么执行？"
  │     ├─ KVCache.decode()
  │     └─ sample → append token
  │
  └─ scheduler.finish(completed)   ← "谁完成？"
        └─ remove from running
```

## Architecture Boundary
```
┌─────────────┐     ┌─────────────┐     ┌──────────────┐
│ StateManager │────►│  Scheduler  │────►│ Request      │
│  (executes)  │     │ (schedules) │     │   Queues     │
└──────┬───────┘     └─────────────┘     └──────────────┘
       │
       ├─ prefill / decode / KV cache
       └─ delegates "who runs" to Scheduler
```

## Current Capability
- ✅ 请求调度独立于执行逻辑
- ✅ Scheduler 拥有独立接口 `schedule()` / `add_request()` / `finish()`
- ✅ FCFS 策略 + max_batch_size 上限

## Current Limitation
- ❌ Scheduler 不知道 KV cache 资源（无法判断是否有足够显存）
- ❌ 无 KVCacheManager —— Scheduler 不知道 request 需要多少 blocks
- ❌ 无法做资源感知的调度（内存不够时仍盲目调度）
- ❌ 无 chunked prefill / priority 等高级策略

## Next Stage
Scheduler 决定执行 request 但不知道显存是否足够。Commit 008 引入 KVCacheManager，使 Scheduler 能感知 KV cache 资源。
