## What C145 did

### 1. `column_parallel_linear.py` (new)

Mirrors `vllm/lora/layers/column_parallel_linear.py:
ColumnParallelLinearWithLoRA` (subset).

- **`ColumnParallelLinearLoRA(BaseLinearLayer)`** — overrides
  `_base_weight_for_lora()` to return the host's
  already-partitioned weight. The LoRA delta is computed in
  the same partitioned space (B is sharded along the output
  axis matching the host). No `all_reduce` needed — the LoRA
  delta is per-rank.

### 2. `row_parallel_linear.py` (new)

Mirrors `vllm/lora/layers/row_parallel_linear.py:
RowParallelLinearLoRA` (subset).

- **`RowParallelLinearLoRA(BaseLinearLayer)`** — overrides
  `_base_weight_for_lora()` to return the host's partitioned
  weight. The LoRA delta computed per-rank requires an
  `all_reduce` across the TP group; we delegate to
  `distributed.parallel_state._TP.all_reduce(...)` (no-op
  when `tp_size == 1`).

### 3. `fused_moe.py` (skeleton)

Mirrors `vllm/lora/layers/fused_moe.py:FusedMoEWithLoRA`.

- **`FusedMoEWithLoRA(BaseLayer)`** — constructor stores the
  host FusedMoE; `create_lora_weights` mirrors the BaseLayer
  API. The per-expert dispatch (routing-aware LoRA delta per
  token) is out of scope per §8.

### 4. `config/lora.py` (extended)

Added `fully_sharded_loras: bool = False` and
`target_modules: list[str] | None = field(default_factory=list)`
to match vLLM's canonical field set. The full vLLM config has
~10 more knobs (`loraplus_*`, `bias_enabled`, `use_routing`,
`alpha`, …); out of scope for my-vllm's minimal subset.
