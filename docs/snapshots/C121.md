# C121: EngineCore.step — top-to-bottom pipeline

## Goal

Tighten `EngineCore.step()` so the hot path reads like nano-vllm's `LLMEngine.step()`:

```
schedule → execute → update_from_output →
finish_completed → kv_transfer → collect_metrics
```

C112 features (LoRA multiplexing, multi-tenant quotas, NIXL P/D, CUDA Event profiling, metrics) stay reachable as side-module helpers, not inlined into `step()`.

## New Features

### `step()` body — 12-line top-to-bottom pipeline

```python
def step(self) -> EngineCoreOutputs:
    self._step_count += 1
    step_start = time.time()

    # 1. P/D consumer recv (no-op unless kv_transfer_config + is_consumer).
    self._maybe_consumer_recv()

    # 2. Schedule: pick what to run this step.
    scheduler_output = self.scheduler.schedule()
    if scheduler_output.total_num_scheduled_tokens == 0:
        return EngineCoreOutputs()

    # 3. Execute: model forward.
    model_output = self.executor.execute_model(scheduler_output)
    if model_output is None:
        return EngineCoreOutputs()

    # 4. Update: scheduler advances req state from model output.
    engine_core_outputs = self.scheduler.update_from_output(
        scheduler_output, model_output,
    )

    # 5. Side concerns (each no-ops if disabled).
    self._finish_completed_requests(engine_core_outputs)
    self._maybe_producer_transfer(engine_core_outputs)
    self._collect_metrics(
        scheduler_output, model_output,
        engine_core_outputs, step_start, time.time(),
    )

    return engine_core_outputs
```

### Side-module helpers

| Helper | Replaces inline logic | Gating |
|---|---|---|
| `_maybe_consumer_recv()` | consumer P/D recv block | `kv_transfer_config.is_kv_consumer` |
| `_maybe_producer_transfer()` | producer P/D ship block | `kv_transfer_config.is_kv_producer` |
| `_finish_completed_requests()` | finish-loop iteration over `engine_core_outputs.outputs` | always |
| `_collect_metrics()` | TTFT/TPOT/ITL/KV-usage/prefix-cache build + log | always |

Each helper early-returns on its gating condition so the no-config path is the same as before.

### Other cleanups

- Removed unused imports: `KVCacheBlocks`, `RecvResult`, `TransferStatus`, `SamplingParams` (now used only inside helpers).
- Producer/consumer helper signatures typed (e.g. `outputs: EngineCoreOutputs` instead of `outputs`).
- Removed duplicate `from my_vllm.v1.request import Request` inside `_consumer_recv_loop`.
- Combined the two branches of the ACK handler in `_drain_acks` (both did `kv_cache_manager.free(req_id)`).

## Runtime Flow

```
EngineCore.step()
  ├─ _maybe_consumer_recv()           # no-op unless P/D + consumer
  ├─ Scheduler.schedule() → SchedulerOutput
  ├─ Executor.execute_model() → ModelRunnerOutput
  ├─ Scheduler.update_from_output() → EngineCoreOutputs
  ├─ _finish_completed_requests()     # free KV blocks, mark FINISHED
  ├─ _maybe_producer_transfer()       # no-op unless P/D + producer
  └─ _collect_metrics()               # build + log Stats
```

## Current Capability

- `python run.py`: identical 50-token output to C120.
- `pytest tests/`: 194 passed / 55 failed — same baseline as C120.
- `step()` body is now 12 lines; helpers each do one thing.
- C112 features (NIXL producer/consumer, LoRA, multi-tenant) still wired and reachable — just not inlined.

## Current Limitation

- `_collect_metrics` is still ~70 lines (TTFT, TPOT, ITL, KV cache usage, prefix-cache hits). Mirrors vLLM `Stats.update_from_output` + `StatLogger.record` exactly — kept verbose for parity.
- P/D `_consumer_recv_loop` and `_producer_transfer_loop` are still long (no internal sub-helpers); they're reachable only when `kv_transfer_config` is set, so they don't affect the default hot path.
- `LLMEngine.step()` (in `entrypoints/llm.py`'s neighbor file) still has the multi-token-result aggregation logic from C116 — out of C121 scope; that's an engine-layer concern.
