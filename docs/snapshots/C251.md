### 2. New dataclasses + helpers

#### `KVOwnership` — per-request ownership record

```python
@dataclass
class KVOwnership:
    request_id: str
    local_block_ids: list[int]
    owner_engine_id: str
    state: str = "owned"
    created_at: float = 0.0
```

Mirrors the implicit ownership state in vLLM's `KVConnectorBase_V1`,
decomposed into a dataclass for clarity.

#### `KVOwnershipState` — lifecycle state machine

```python
class KVOwnershipState(enum.Enum):
    ALLOCATED = "allocated"     # allocated but not yet filled
    OWNED = "owned"            # filled and owned by local engine
    TRANSFERRING = "transferring"  # being transferred to remote
    LEASED = "leased"          # leased to remote engine
    EXPIRED = "expired"        # remote engine's lease ran out
    FREED = "freed"            # freed back to the free pool
```

#### `KVIndex` + `KVIndexEntry` — two-way block index

```python
class KVIndex:
    def add(request_id, block_ids)      # register blocks for a request
    def remove(request_id) -> list[int] # cleanup, returns removed blocks
    def remove_block(block_id) -> str   # remove single block
    def update_state(request_id, state, block_ids=None) -> int
    def get_blocks_for_request(request_id) -> list[int]
    def get_request_for_block(block_id) -> str | None
    def get_state(request_id, block_id=None) -> KVOwnershipState
    def get_blocks_in_state(state) -> list[(request_id, block_id)]
    def clear()
    def __len__()  # total block count
    def __contains__(block_id)  # block presence check
```

Pure-Python (no numpy / torch dependency), so usable in tests + in the
scheduler thread without GIL contention.

#### `KVFailureTracker` + `KVTransferFailure` — failure retransmission

```python
class KVTransferFailure:
    request_id: str
    failed_block_ids: list[int]
    num_completed_tokens: int
    error_message: str
    timestamp: float

class KVFailureTracker:
    def record_failure(request_id, failed_block_ids,
                       num_completed_tokens=0, error_message="")
    def get_failure(request_id) -> KVTransferFailure | None
    def has_failure(request_id) -> bool
    def get_failed_block_ids(request_id) -> list[int]
    def clear(request_id)
    def prune_stale(now=None) -> int  # drop expired records
```

Used by the producer to issue re-transfers of only the failed blocks
(partial transfer recovery).  Mirrors vLLM's implicit failure
recording at `vllm/.../v1/base.py:357-393`.

### 3. Extended `KVConnectorBase_V1` surface

New default implementations on the ABC:

* **Metadata lifecycle**: `bind_connector_metadata` /
  `clear_connector_metadata` / `_get_connector_metadata` /
  `has_connector_metadata` — round-trip the bound per-step metadata.
* **KV cache registration**: `register_kv_caches` /
  `register_cross_layers_kv_cache` / `set_host_xfer_buffer_ops`
  — store the references; subclass overrides compute NIXL descriptors.
* **Block pool binding**: `bind_gpu_block_pool` — store the bound pool
  for `handle_preemptions` block-ID translation.
* **Failure API**: `get_block_ids_with_load_errors` /
  `get_finished` / `get_finished_count` — pull completed / failed
  transfer IDs.
* **Handshake metadata**: `get_handshake_metadata` /
  `set_xfer_handshake_metadata` — round-trip the local handshake
  payload.
* **Worker→Scheduler metadata**: `build_connector_worker_meta` —
  subclass override returns per-worker stats.
* **Lifecycle hooks**: `on_new_request` / `update_connector_output` /
  `take_events` / `has_pending_push_work` / `shutdown` / `reset_cache` —
  no-op defaults; subclass overrides extend.
* **Stats**: `get_kv_connector_stats` — returns the bound stats object.
* **Block layout hints**: `get_required_kv_cache_layout` (classmethod) /
  `prefer_cross_layer_blocks` (property) — declare layout preferences.

The `__init__` now also instantiates:
* `self._kv_index: KVIndex = KVIndex()`
* `self._failure_tracker: KVFailureTracker = KVFailureTracker()`
* `self._gpu_block_pool: Any = None`
* `self._kv_caches: dict[str, torch.Tensor] = {}`
* `self._xfer_handshake_metadata: KVConnectorHandshakeMetadata | None = None`
* `self._finished_req_ids: set[str] = set()`
* `self._failed_req_ids: set[str] = set()`
* `self._stats: Any = None`

So NIXL connector (C250) inherits the full C251 surface without
needing to override anything beyond the abstract methods.

### 4. Updated default `update_state_after_alloc` / `request_finished`

The C133-era `update_state_after_alloc` was a no-op; C251 wires it to
register the newly allocated blocks in the `KVIndex` (so
`request_finished` can find them):

```python
def update_state_after_alloc(self, request, blocks, num_external_tokens):
    request_id = getattr(request, "request_id", str(request))
    block_ids = list(blocks) if blocks else []
    if block_ids:
        self._kv_index.add(request_id, block_ids)
        self._kv_index.update_state(request_id, KVOwnershipState.ALLOCATED)
```

`request_finished` is now a default that removes the request from
the KV index + clears any failure record + removes the per-step
finished / failed sets:

```python
def request_finished(self, request, block_ids):
    request_id = getattr(request, "request_id", str(request))
    if block_ids:
        for block_id in block_ids:
            self._kv_index.remove_block(block_id)
        if not self._kv_index.get_blocks_for_request(request_id):
            self._kv_index.remove(request_id)
    else:
        self._kv_index.remove(request_id)
    self._failure_tracker.clear(request_id)
    self._finished_req_ids.discard(request_id)
    self._failed_req_ids.discard(request_id)
```

Subclasses can still override for richer bookkeeping.

   │     ├── connector.on_new_request(req)
   │     │     └── (skeleton: no-op)
   │     ├── connector.get_num_new_matched_tokens(req, num_computed)
   │     │     └── returns matched token count (subclass override)
   │     ├── update_state_after_alloc(req, blocks, num_external)
   │     │     └── _kv_index.add(req_id, blocks)         ← C251
   │     │         _kv_index.update_state(ALLOCATED)
   │     ├── build_connector_meta(scheduler_output)
   │     │     └── returns NixlConnectorMetadata
   │     └── after forward:
   │           ├── connector.update_connector_output(output)
   │           └── connector.take_events()
   │
   ├── Worker:
   │     ├── connector.register_kv_caches(kv_caches)     ← C251
   │     │     └── _kv_caches = dict(kv_caches)
   │     ├── connector.bind_connector_metadata(meta)      ← C251
   │     ├── start_load_kv(forward_context)
   │     │     └── posts NIXL READ xfers (or local SHM)
   │     ├── save_kv_layer(layer, kv)
   │     │     └── records kv_layer for NIXL WRITE
   │     ├── wait_for_layer_load / wait_for_save
   │     ├── check_transfer_done(timeout)

   │     ├── get_block_ids_with_load_errors()             ← C251
   │     │     └── _failure_tracker.get_failed_block_ids()

   │     └── send_ack(req_id, success)
   │           └── _acks[req_id] = success
   │

   │     if get_block_ids_with_load_errors() is non-empty:

## Current Capability

* **Full KV ownership / index / failure tracking** — every
  `KVConnectorBase_V1` subclass (NIXL, Example, …) gets the C251
  surface for free via inheritance.
* **Partial transfer** — `RecvResult.valid_prefix_tokens` plumbed
  through `get_block_ids_with_load_errors` + `_failure_tracker` so
  the scheduler can issue recomputes from the right offset.
* **Failure retransmission loop** — `record_failure` (consumer)
  → `get_failed_block_ids` (scheduler) → re-issue NIXL READ for
  just those blocks.
* **Metadata lifecycle** — `bind_connector_metadata` /
  `clear_connector_metadata` round-trip the per-step metadata object
  in the engine; `get_handshake_metadata` /
  `set_xfer_handshake_metadata` round-trip the local handshake payload.
* **NIXL connector (C250) integration** — `NixlConnector` /
  `NixlPullConnector` / `NixlPushConnector` now expose
  `kv_index` + `failure_tracker` properties + `register_kv_caches`
  inherited from the base.

## Current Limitation

1. **C250 NIXL runtime still skeleton** — the actual NIXL RDMA path
   is still not vendored; the C251 surface is fully exercisable
   in single-process mode via the local SHM backend.
2. **No `handle_preemptions` logic** — the default is a no-op;
   subclass overrides would translate preempted block IDs to remote
   block IDs and re-issue transfers.
3. **No `update_connector_output` parser** — the default is a no-op;
   subclass overrides would extract release deadlines from the
   worker's connector output.
4. **No `take_events` events** — the default returns empty;
   subclass overrides would yield `KVCacheEvent`s for the metrics
   subsystem (C252 ties into this).
5. **Failure tracker not pruned by default** — the scheduler must
   call `prune_stale()` periodically; otherwise the dict grows.
