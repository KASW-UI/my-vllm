# C117: triton_attn + selector — switch default backend to TritonAttentionBackend

## Goal

Make `TritonAttentionBackend` the default attention backend for the runner, and fix the KV cache layout mismatch between the runner's per-K/per-V tensors and the Triton kernel's expected HND-packed layout.

## New Features

### KV cache layout — HND packed

The runner now allocates a **single combined buffer** in HND-packed layout (matches vLLM `TritonAttentionBackend.get_kv_cache_shape`):

```
kv_cache: [num_layers, num_blocks, num_kv_heads, block_size, 2 * head_dim]
K = kv_cache[..., :head_dim]
V = kv_cache[..., head_dim:]
```

`bind_kv_cache` passes the per-layer 5D tensor as a single argument (not a tuple).

### TritonAttentionBackend splits the cache at call time

`TritonAttentionImpl.forward` follows the real vLLM pattern (`vllm triton_attn.py:821`):

```python
# (B, H, N, 2*hs).transpose(1, 2) → (B, N, H, 2*hs) → split on last dim.
key_cache, value_cache = kv_cache.transpose(1, 2).split(self.head_size, dim=-1)
triton_reshape_and_cache_flash(key=..., value=..., key_cache=key_cache, value_cache=value_cache, ...)
unified_attention(q=..., k=key_cache, v=value_cache, ...)
```

This produces separate flash-layout tensors `(num_blocks, block_size, num_kv_heads, head_size)` for both kernels.

### Triton kernel arg translation

The `unified_attention` wrapper computes `softcap > 0` and `1 + window_size[0]` as `tl.constexpr` — both blow up on `None`. The impl translates:
- `self.sliding_window = None` → `window_size=(-1, -1)`
- `self.logits_soft_cap = None` → `softcap=0.0`

These match the real vLLM `TritonAttentionImpl.forward` non-quant path.

### Selector default switched

`v1/attention/selector.py:get_attn_backend()` now returns `TritonAttentionBackend` (was `FlashAttentionBackend`). `Attention.get_attn_backend()` delegates to the selector.

## Current Capability

- `python run.py`: same 50-token output as C116 — Triton backend produces identical sampled tokens to SDPA fallback (same model, same weights, same kernel math).
- 191 passed / 55 failed — same baseline as C116. TestSelector updated to assert `TritonAttentionBackend` (was `FlashAttentionBackend`).
- The hot path now uses the real vLLM Triton kernels (`triton_reshape_and_cache_flash` + `unified_attention`) instead of the SDPA-based `FlashAttentionImpl`.

## Current Limitation

- `TritonAttentionBackend.get_kv_cache_shape` returns `(num_blocks, num_kv_heads, block_size, 2 * head_size)` (HND packed). The engine's KV cache allocator (`KVCacheManager`) doesn't currently consume this — it's still using its own internal block layout. End-to-end P/D disaggregation or pre-allocation via `kv_cache_spec` is not exercised yet.
- `TritonAttentionImpl` is invoked only via the runner's manual `_bind_kv_caches` flow. The `static_forward_context` registration (where `Attention.__init__` would self-register its layer name under `compilation_config.static_forward_context`) is not wired — out of scope until C119.
- KV cache dtype is hardcoded `"auto"` (no FP8 path); `k_scale` / `v_scale` are `1.0`. Matches vLLM's non-quant path; quantization is a later P1 item.
- `FlashAttentionBackend` is still importable as a fallback but not selected by the default `get_attn_backend()`.
