# C025: Output Processing Pipeline

## Goal

Extract output processing (token→text, EOS/max_tokens detection,
structured output formatting) from EngineCore.step() and LLMEngine
into dedicated OutputProcessor and IncrementalDetokenizer components,
following vLLM V1's `v1/engine/output_processor.py` + `detokenizer.py`.

## New Features

- `v1/engine/detokenizer.py` — `IncrementalDetokenizer`:
  - Wraps tokenizer for incremental token→text conversion
  - `update(new_token_ids)` → delta text (only new tokens since
    last call)
  - `full_text()` → decoded full output text
  - `token_ids` → list of all accumulated token IDs
  - Handles `tokenizer=None` gracefully (empty strings)
- `v1/engine/output_processor.py` — `OutputProcessor`:
  - `process_outputs(model_output, req_map, eos_token_id,
    max_tokens)` → `list[RequestOutput]`
  - Per-request EOS detection and max_tokens limit checking
  - Delegates token→text to IncrementalDetokenizer
  - `RequestOutput` dataclass: request_id, prompt_text,
    output_text, delta_text, output_tokens, prompt_tokens,
    finish_reason, finished, token_ids
  - `cleanup(request_id)` for detokenizer state cleanup
- EngineCore:
  - `self.output_processor = OutputProcessor(tokenizer)`
  - `step()` now returns `list[RequestOutput]` (filtered to
    finished only for backward compat)
  - `_finish_request()` calls `output_processor.cleanup(rid)`
- LLMEngine:
  - `step()` receives `RequestOutput` instead of raw `Request`;
    formats results dict with prompt_text, output_text, delta_text
  - Falls back to own tokenizer for prompt_text when EngineCore
    has no tokenizer

## File Tree

```
my_vllm/v1/engine/
├── detokenizer.py          ← NEW: IncrementalDetokenizer
├── output_processor.py     ← NEW: OutputProcessor + RequestOutput
├── core.py                 ← updated: uses OutputProcessor
└── llm_engine.py           ← updated: receives RequestOutput
```

## Current Limitation

- `IncrementalDetokenizer` does basic full-token decode per step
  (no sub-token level streaming or stop string detection)
- `OutputProcessor` returns only finished outputs from `step()`
  for backward compat; intermediate per-step outputs available
  internally but not exposed via EngineCore API
- No LogprobsProcessor integration (logprobs not yet wired)
