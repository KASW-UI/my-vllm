# C244 — Quick AllReduce + FlashInfer AllReduce 笔记

> Closes the B-level "Quick AllReduce + FlashInfer AllReduce 笔记" gap
> from `phase3-distributed-runtime-plan.md` § Phase 3.
>
> Two third-party allreduce acceleration paths (ROCm QuickReduce +
> FlashInfer-AR) shipped as **class skeletons + comprehensive
> engineering notes**.  Both are CUDA-irrelevant on the dev box
> (QuickReduce is ROCm MI300-only; FlashInfer-AR needs the
> `flashinfer` library); the value is the architectural documentation.

## Goal

Document vLLM's allreduce dispatch chain (NCCL / Custom AR /
QuickReduce / FlashInfer-AR) so future readers can reason about
backend selection without re-deriving it from the vLLM source.

Specific deliverables:

1. `QuickAllReduce` skeleton (`my_vllm/distributed/device_communicators/quick_all_reduce.py`)
   with the `QuickReduceRegime` enum + `_QR_MIN_SIZE` table preserved
   verbatim from vLLM.  All codepaths disabled (no ROCm, no C ext).
2. `FlashInferAllReduce` skeleton
   (`my_vllm/distributed/device_communicators/flashinfer_all_reduce.py`)
   with workspace management shape preserved.  All codepaths disabled
   (no flashinfer vendored).
3. Engineering deep-dive (≥ 300 lines):
   `docs/notes/quick-allreduce.md` covering quantization codecs,
   mnnvl vs trtllm backends, fusion patterns, dispatch chain, scope
   reductions, deployment notes, references.
4. Tests verifying the disabled-flag behavior, the regime enum, the
   min-size table, and the workspace helper shape.

## Runtime Flow

Both skeletons share the same dispatch pattern: the heuristic
returns False unconditionally, and the call surface raises
`RuntimeError` to make accidental use loud.

```
QuickAllReduce (ROCm MI300 + C ext)         FlashInferAllReduce (flashinfer + CUDA)
──────────────────────────────              ──────────────────────────────────────
__init__(group, device)                      __init__(group, device)
  └─ disabled = True (no ROCm)                 └─ disabled = True (no flashinfer)

should_quick_allreduce(inp) → False          should_use_fi_ar(inp) → False
                                             (heuristic checks: CUDA + 2D + size)
quick_all_reduce(inp) → RuntimeError         all_reduce(inp) → RuntimeError
                                             (would call flashinfer_comm.allreduce_fusion)
close() → no-op                              destroy() → no-op
```

## Current Capability

* **Class skeletons** matching vLLM's API surface (callers can import
  the symbols and call lifecycle methods without crashing).
* **`QuickReduceRegime` enum** with integer ids aligned to the
  upstream C header.
* **`_QR_MIN_SIZE` table** preserved verbatim from vLLM as a
  reference.
* **`FlashInferAllReduce` lifecycle** preserved: heuristic checks,
  workspace helpers, `atexit` registration.
* **30 tests** covering availability flags, enum ordering, disabled
  behavior, no-op lifecycle, and table consistency.
* **307-line engineering note** explaining the dispatch chain,
  quantization codecs, mnnvl vs trtllm, fusion patterns, scope
  reductions, and deployment guidance.

## Current Limitation

* **No QuickReduce runtime** — the C extension isn't vendored; the
  ROCm-only kernel can't run on the CUDA dev box.
* **No FlashInfer runtime** — `flashinfer.comm` isn't vendored.
* **No backend selection logic** — the dispatch chain lives in
  `CudaCommunicator` (C214) which already wires Custom AR +
  SymmMem; QuickReduce / FlashInfer-AR would extend the same chain
  when their respective libraries are vendored.
* **No per-world-size `max_workspace_size_mb` table** — preserved in
  FlashInfer-AR via comments only; would need
  `PassConfig.default_fi_allreduce_fusion_max_size_mb()` from vLLM
  for a complete port.
