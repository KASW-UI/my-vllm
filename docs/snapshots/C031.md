- `my_vllm/config.py` — `EngineConfig` dataclass:
  Centralized configuration (model, cache, scheduler, execution
  parameters). Previously scattered across constructors.
- `v1/serial_utils.py` — `MsgpackEncoder`/`MsgpackDecoder`:
  Stub for future multiprocess executor IPC serialization.
- `v1/metrics/__init__.py` — bridges `MetricsCollector` from
  the legacy `metrics/` module into the v1 namespace.
- `v1/attention/backends/flash_attn.py` — `FlashAttentionBackend`:
  Stub requiring CUDA FlashAttention extension; raises
  `NotImplementedError` to signal the hardware backend gap.
- `model_executor/model_loader.py` — bridge from `runtime/model_loader.py`
- `model_executor/models/opt.py` — bridge from `runtime/models/opt.py`
- 59 C031 target files verified present (file tree test)

| Prompt | Tokens | Prefill (ms) | Prefill ms/tok | Decode (5 steps, ms) | Decode tok/s |
|------|------|------|------|------|------|
| short ("Hello world") | 3 | 146.2 | 48.74 | 20.1 | 248.6 |
| medium (14 words) | 14 | 2.4 | 0.17 | 13.9 | 360.4 |
| long (37 words) | 37 | 4.3 | 0.12 | 10.2 | 490.3 |

> Notes: Prefill first token incurs model warmup (146 ms for short). Subsequent prefill latency is < 0.2 ms/token. Decode throughput ~250-500 tok/s (single request, greedy sampling, batch_size=1). Run `python examples/benchmark.py` to reproduce.

## Current Limitation

- FlashAttention requires CUDA extension (stub only)
- `MsgpackEncoder` is JSON-based, not true msgpack
- No CUDA Graph, no Speculative Decode (intentionally excluded)
- No distributed (TP>1, PP) — UniProcExecutor only
- No Prometheus HTTP endpoint — `MetricsCollector` is in-process only
